# @moderno-ui/docs

Bilingual (en/es) Astro docs for Moderno: MDX + Content Collections, Svelte
islands for live previews, a page-wide framework selector, an autogenerated
`<PropsTable>`, a **Theme Builder**, and the static registry served under `/r/`.

## Scripts

| Script              | What it does                                                     |
| ------------------- | ---------------------------------------------------------------- |
| `pnpm dev`          | Prebuild (props + registry) then `astro dev`.                    |
| `pnpm build`        | Prebuild → `astro build` → per-locale Pagefind index.            |
| `pnpm typecheck`    | `astro check`.                                                   |
| `pnpm check:parity` | Fail if any docs slug lacks an en/es translation (the CI guard). |
| `pnpm test:e2e`     | Playwright assertions over the built `dist/` (see below).        |

## Build pipeline

1. **prebuild** — `@moderno-ui/props-doc` resolves the React types into
   `src/generated/props/*.json`; `scripts/copy-registry.ts` copies the repo
   `registry/` into `public/r/`.
2. **astro build** — static HTML, the `.md` twin per page, and `llms.txt` per
   locale.
3. **index** — Pagefind indexes `dist/en` and `dist/es` into separate bundles
   (`dist/<locale>/pagefind`) so search never mixes languages.

## Authoring a component page: Preview, examples, framework selector

A component page's live demo follows one convention, so a page written under
a future ticket needs no migration later (CONTEXT.md: "Preview", "Example",
"Framework selector").

1. **The source lives in files, one per framework**, under
   `src/examples/<component>/`: `react.tsx` and `solid.tsx`, `vue.vue`,
   `<component>.svelte` (named after the component, not generically
   `svelte.svelte` — see the note in `tests/e2e/guards.spec.ts` on why that
   name has to be unique). Never a `code={`…`}`` string literal in the MDX —
that is the drift bug the file convention exists to close. A block's
example is the registry item itself: import straight from
`registry/blocks/<name>/<framework>/`.
2. **The Svelte file is the one mounted.** It is imported twice — once as a
   component (`import ButtonDemo from "../../../examples/button/button.svelte"`)
   for `<ButtonDemo client:visible />`, and once as text
   (`import svelteExample from "../../../examples/button/button.svelte?raw"`)
   for the Preview's source panel — so the shown Svelte source can never drift
   from what actually renders. `react.tsx`/`vue.vue`/`solid.tsx` are
   raw-imported the same way but only ever shown, never mounted; a Solid file
   needs a leading `/** @jsxImportSource solid-js */` pragma so `astro check`
   (which assumes React JSX project-wide) reads it correctly.
3. **Wire `<Preview>` with all four**, and put one `<FrameworkSelect>` above
   it — once per page, and only on a page that has a Preview or an Install:

   ```mdx
   import Preview from "../../../components/Preview.astro";
   import FrameworkSelect from "../../../components/FrameworkSelect.astro";
   import ButtonDemo from "../../../examples/button/button.svelte";
   import reactExample from "../../../examples/button/react.tsx?raw";
   import vueExample from "../../../examples/button/vue.vue?raw";
   import solidExample from "../../../examples/button/solid.tsx?raw";
   import svelteExample from "../../../examples/button/button.svelte?raw";

   <FrameworkSelect locale="en" />

   <Preview
     examples={{ react: reactExample, vue: vueExample, solid: solidExample, svelte: svelteExample }}
   >
     <ButtonDemo client:visible />
   </Preview>
   ```

   `<Install pkg="@moderno-ui/react" />` needs no change — it derives the
   other three frameworks' package names from the one it's given.

4. **Typecheck coverage rides on the framework's own `tsconfig.json`.** Each
   of `packages/{react,vue,solid,svelte}/tsconfig.json` includes
   `apps/docs/src/examples/**/<ext>` for its own extension, so `pnpm typecheck`
   already covers a new example the moment the file exists — nothing to wire
   up per page.

## End-to-end checks

`tests/e2e` serves the built `dist/` and asserts facts about it: that the
sidebar lists exactly the locale's docs pages in a stable order with the right
current row, that every island in `src/islands` **and** every component
Example in `src/examples` hydrates on some **preview page**, that the
framework selector switches every Preview's source panel and the Install
command together and the choice survives a real navigation
(`framework-select.spec.ts`), and — in `preview-cascade.spec.ts` — which CSS
rule actually wins inside a live `<Preview>` panel. All text and computed
styles, no screenshots.

This used to also compare 204 committed pixel baselines per platform. They were
dropped: almost every PR touches a token, a stylesheet or a page, so the
baselines needed regenerating through a CI round-trip nearly every time, which
cost far more than the diffs caught. Check visual changes by looking at the
docs preview.

## i18n

Every page exists under `src/content/docs/<locale>/<slug>.mdx`. `check:parity`
(wired into CI as `pnpm docs:parity`) fails the build if a slug is missing in
either locale. Prop names and code identifiers stay in English in both locales;
only the surrounding labels are translated (`src/i18n/ui.ts`).

## Deploy (Vercel)

The `@astrojs/vercel` adapter emits `.vercel/output` (Build Output API v3).

- Set the Vercel project **Root Directory** to `apps/docs`.
- Domain: `moderno.style` (falls back to the generated Vercel URL until the
  domain is registered).
- `SITE_URL` env var overrides the canonical/`llms.txt` base URL for preview
  deploys; the CLI can point at a per-PR preview registry at `<url>/r/`.
