## Referencia de API

### Propiedades

| Prop           | Tipo                                                                          | Por defecto             | Descripción                                                                     |
| -------------- | ----------------------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------- |
| `mode`         | `"sign-in" \| "sign-up" \| "forgot-password" \| "reset-password" \| "verify"` | `"sign-in"`             | Qué tarjeta se muestra. Ver [Modos](#modos).                                    |
| `titleLevel`   | `1 \| 2 \| 3`                                                                 | `3`                     | Rango de encabezado del título; una pantalla completa pasa `1`.                 |
| `sent`         | `boolean`                                                                     | `false`                 | `forgot-password`: la tarjeta confirma que el enlace salió.                     |
| `sentTo`       | `string`                                                                      | `""`                    | `forgot-password`, `verify`: la dirección, nombrada y enviada como `email`.     |
| `codeLength`   | `number`                                                                      | `6`                     | `verify`: el número de celdas del código.                                       |
| `resendIn`     | `number`                                                                      | `0`                     | `verify`: segundos hasta que se desbloquea el reenvío. El temporizador es tuyo. |
| `resent`       | `boolean`                                                                     | `false`                 | `verify`: el encabezado dice que va en camino un código nuevo.                  |
| `token`        | `string`                                                                      | `""`                    | `reset-password`: el token del correo, enviado como `token` oculto.             |
| `requirements` | `PasswordRequirement[]`                                                       | tres reglas sin cumplir | `reset-password`: reglas bajo la contraseña nueva; `[]` muestra texto de ayuda. |
| `error`        | `string`                                                                      | —                       | Alerta de formulario. En `sign-in` también invalida los dos campos.             |
| `errors`       | `Record<string, string>`                                                      | —                       | Mensajes por campo según su `name`. No se lee en `sign-in`.                     |
| `loading`      | `boolean`                                                                     | `false`                 | Deshabilita todos los controles y marca el envío con `aria-busy`.               |
| `disabled`     | `boolean`                                                                     | `false`                 | El formulario no está disponible, p. ej. un espacio solo con SSO.               |
| `onSubmit`     | `(event) => void`                                                             | —                       | El evento submit nativo. Svelte: `onsubmit`. Vue: `@submit`.                    |
| `forgotHref`   | `string`                                                                      | `"#"`                   | `sign-in`: el enlace "Forgot your password?".                                   |
| `signUpHref`   | `string`                                                                      | `"#"`                   | `sign-in`: el enlace "Create an account".                                       |
| `signInHref`   | `string`                                                                      | `"#"`                   | Los demás modos: el enlace "Sign in".                                           |
| `termsHref`    | `string`                                                                      | `"#"`                   | `sign-up`: el enlace a los términos bajo la casilla de consentimiento.          |
| `privacyHref`  | `string`                                                                      | `"#"`                   | `sign-up`: el enlace a la privacidad bajo la casilla de consentimiento.         |

### PasswordRequirement

| Campo   | Tipo      | Descripción                                            |
| ------- | --------- | ------------------------------------------------------ |
| `id`    | `string`  | Clave estable de la fila.                              |
| `label` | `string`  | La regla en palabras, p. ej. "At least 12 characters". |
| `met`   | `boolean` | Si el valor actual la cumple. Lo calculas tú.          |

### Modos

| Modo                    | Campos                                    | Nombres enviados                         | Enlace del pie                     |
| ----------------------- | ----------------------------------------- | ---------------------------------------- | ---------------------------------- |
| `sign-in` (por defecto) | Email, contraseña, recordarme             | `email`, `password`, `remember`          | "New here? Create an account"      |
| `sign-up`               | Nombre, email, contraseña, consentimiento | `fullName`, `email`, `password`, `terms` | "Already have an account? Sign in" |
| `forgot-password`       | Email; con `sent`, una confirmación       | `email`                                  | "Remembered it? Sign in"           |
| `reset-password`        | Contraseña nueva, confirmación, reglas    | `password`, `confirmPassword`, `token`   | "Changed your mind? Sign in"       |
| `verify`                | Una celda por dígito, un botón de reenvío | `code`, `email`, `intent`                | "Wrong account? Sign in"           |

Cada modo tiene también una vista previa en su pantalla: [acceso](/es/sign-in/), [registro](/es/sign-up/), [recuperación](/es/forgot-password/), [contraseña nueva](/es/reset-password/) y [verificación](/es/verify/).

### Estados

| Estado            | Prop                     | Qué se muestra                                                                    |
| ----------------- | ------------------------ | --------------------------------------------------------------------------------- |
| Por defecto       | —                        | El formulario vacío con placeholders.                                             |
| Deshabilitado     | `disabled`               | Todos los controles deshabilitados.                                               |
| Cargando          | `loading`                | Todos los controles deshabilitados; el envío muestra un spinner y `aria-busy`.    |
| Error             | `error`                  | Una alerta de formulario; en `sign-in` los dos campos quedan inválidos.           |
| Errores de campo  | `errors`                 | El campo nombrado queda inválido e imprime su mensaje. No en `sign-in`.           |
| Enviado           | `sent`                   | `forgot-password`: "Check your inbox", y el envío pasa a "Send it again".         |
| Reglas            | `requirements`           | `reset-password`: cada regla dice "met" o "not met yet".                          |
| Código rechazado  | `errors={{ code: "…" }}` | `verify`: todas las celdas quedan inválidas y el mensaje se imprime como `alert`. |
| Reenvío bloqueado | `resendIn`               | `verify`: el reenvío está deshabilitado y muestra los segundos restantes.         |
| Reenviado         | `resent`                 | `verify`: el encabezado dice que salió un código nuevo y el anterior ya no sirve. |

### Dimensionado

La tarjeta se limita a `--container-sm` (24rem) y responde a su contenedor, no al viewport. La fila de recordarme se apila por debajo de `@sm` y el título crece en `@md`.

## Notas

- Es presentacional: no guarda credenciales ni envía peticiones. Gestiona tú el submit nativo.
- Un error de `sign-in` nunca dice qué campo falló, así no confirma que exista una cuenta.
- La confirmación de `forgot-password` dice "if that address has an account" exista o no.
- El reenvío, el token del correo y la dirección viajan en el formulario: todo envío funciona sin JavaScript.
- En `forgot-password` y `verify` el encabezado es una región viva, así que `sent` y `resent` se anuncian.
- Las reglas son el texto de ayuda del campo y una región viva educada; el servidor debe validarlas igual.
