## Referencia de API

### Props

Los callbacks son props `on…` en React y Solid, en minúsculas (`onstepchange`) en Svelte, y emits (`stepChange`, `complete`) en Vue.

| Prop           | Tipo               | Por defecto      | Descripción                                                            |
| -------------- | ------------------ | ---------------- | ---------------------------------------------------------------------- |
| `initialStep`  | `OnboardingStep`   | `"welcome"`      | La pantalla con la que abre el flujo; en una app, la que diga la ruta. |
| `initialName`  | `string`           | `""`             | El nombre completo, si el registro ya lo pidió.                        |
| `hrefFor`      | `(step) => string` | `` `#${step}` `` | La URL de cada paso; la usan los enlaces para saltar.                  |
| `finishHref`   | `string`           | `"#"`            | Donde empieza la app: el destino de Saltar en el último paso.          |
| `onStepChange` | `(step) => void`   | —                | El flujo se movió; refléjalo en la URL.                                |
| `onComplete`   | `(result) => void` | —                | La persona terminó, o se lo saltó.                                     |
| `homeHref`     | `string`           | `"#"`            | Destino del logotipo en cada pantalla.                                 |
| `supportHref`  | `string`           | `"#"`            | Destino de "Contact support" en welcome.                               |
| `salesHref`    | `string`           | `"#"`            | Destino de "Talk to sales" en plan-select.                             |
| `privacyHref`  | `string`           | `"#"`            | Destino de los enlaces de privacidad en cada pantalla.                 |
| `termsHref`    | `string`           | `"#"`            | Destino de los enlaces de términos en cada pantalla.                   |

`result` es `{ name: string; plan?: string; invites: string[] }`: el nombre guardado, el `id` del plan elegido y cada dirección invitada.

### Pasos

`OnboardingStep` es una de las cuatro pantallas, en el orden en que el flujo las recorre.

| Paso                                  | Sale hacia                                                              |
| ------------------------------------- | ----------------------------------------------------------------------- |
| [`welcome`](/es/welcome/)             | `profile-setup` con Continue; `onComplete` con Skip for now             |
| [`profile-setup`](/es/profile-setup/) | `plan-select` al guardar el perfil o con Skip; `welcome` con Cancel     |
| [`plan-select`](/es/plan-select/)     | `invite-team` al elegir un plan                                         |
| [`invite-team`](/es/invite-team/)     | `onComplete` con Continue o Skip; enviar invitaciones no cambia de paso |

### Estado

Lo que guarda el ensamblaje para que las pantallas no tengan que hacerlo.

| Estado                   | Guarda                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------- |
| `step`                   | La pantalla que está en la ruta.                                                             |
| `name`                   | El nombre completo; welcome saluda con la primera palabra y el avatar muestra sus iniciales. |
| `avatarSrc`              | La foto elegida, como URL de objeto local.                                                   |
| `plan`                   | El `id` del plan elegido.                                                                    |
| `invites`                | Las direcciones enviadas hasta ahora, en la lista de pendientes.                             |
| `errors` / `emailsError` | Lo que rechazó el último envío. Se borra en cada movimiento.                                 |

## Notas

- El ensamblaje es código de ejemplo, el único archivo que se espera que reescribas. Las pantallas quedan como vienen.
- Los enlaces para saltar solo toman el clic izquierdo simple; los clics con modificador o con el botón central van al navegador.
- El ensamblaje revisa los formularios de perfil e invitaciones como puede hacerlo un formulario por sí solo. Cambia esas revisiones por tus peticiones.
- La foto se queda en el navegador como URL de objeto. Súbela y devuelve tu URL.
- `onComplete` devuelve el flujo a welcome y no dibuja página de éxito; salir es trabajo de tu router.
