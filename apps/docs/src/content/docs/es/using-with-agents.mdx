## Configuración

1. Añade el servidor `moderno` a la configuración MCP de tu agente (Claude Code, Cursor y otros clientes MCP).

   ```json
   {
     "mcpServers": {
       "moderno": {
         "command": "npx",
         "args": ["-y", "@moderno-ui/mcp"]
       }
     }
   }
   ```

2. Arranca el agente desde la raíz del proyecto, donde está instalado `@moderno-ui/*`.

3. Opcional: escribe las reglas y el ciclo de abajo en `AGENTS.md` (`--claude` añade un `CLAUDE.md` gemelo).

   ```sh
   npx @moderno-ui/cli init --claude
   ```

- Servidor local por stdio: sin cuenta, sin endpoint alojado. Necesita Node 22 o superior.
- Lee `moderno.agent.json` de `node_modules/@moderno-ui/*` una sola vez, al arrancar.
- Las respuestas corresponden a las versiones instaladas, no a la última publicada.

## El DESIGN.md del tema

Un tema añadido con la CLI trae su `DESIGN.md`: en la raíz del proyecto si el tema reemplaza al de por defecto, o en `design/<theme>/DESIGN.md` si es un tema de marca. Contiene los valores de la marca, las reglas que sigue todo tema de Moderno y las notas propias de la marca. Menciónalo en `AGENTS.md` para que el agente lo lea antes de dar estilos; las herramientas de abajo cubren los componentes y el contrato.

## Herramientas

Las herramientas leen y verifican; el agente escribe el código él mismo.

| Herramienta         | Entrada              | Devuelve                                                                           |
| ------------------- | -------------------- | ---------------------------------------------------------------------------------- |
| `search_components` | `query`, `framework` | Componentes ordenados por intención, con ruta de import y cuándo usarlos.          |
| `get_component_api` | `name`, `framework`  | Props, `data-part`s y variantes del paquete instalado.                             |
| `get_contract`      | ninguna              | Slots de tokens, el modelo de modo oscuro y multimarca, la convención `data-part`. |
| `get_examples`      | `name`, `framework`  | Snippets funcionales en la sintaxis propia de ese framework.                       |
| `validate_usage`    | `code`, `framework`  | Hallazgos de las reglas. Una lista vacía significa que está limpio.                |

`framework` es uno de `react`, `vue`, `svelte`, `solid` o `astro`.

## El ciclo del agente

### 1. Buscar por intención

```
search_components({ query: "modal blocking decision", framework: "react" })
→ { matches: [{ name: "Dialog", score: 0.82, … }, { name: "Button", score: 0.11, … }] }
```

### 2. Leer la API instalada

```
get_component_api({ name: "Dialog", framework: "react" })
→ { package: "@moderno-ui/react", version: "0.3.0", framework: "react", component: { … } }
```

### 3. Consultar el contrato

Hazlo antes de escribir cualquier color, radio, espaciado, elevación o ancho de contenedor.

```
get_contract()
→ { package: "@moderno-ui/tokens", slots: { color: ["--background", "--foreground", …] }, rules: […] }
```

### 4. Obtener un ejemplo nativo

Pide el framework de destino en lugar de traducir a mano un ejemplo de React.

```
get_examples({ name: "Dialog", framework: "react" })
```

### 5. Escribir el código

```tsx
import { Button, Dialog, Portal } from "@moderno-ui/react";

<Dialog.Root>
  <Dialog.Trigger asChild>
    <Button variant="destructive">Eliminar cuenta</Button>
  </Dialog.Trigger>
  <Portal>
    <Dialog.Backdrop />
    <Dialog.Positioner>
      <Dialog.Content>
        <Dialog.Title>¿Eliminar cuenta?</Dialog.Title>
        <Dialog.CloseTrigger asChild>
          <Button variant="destructive">Confirmar</Button>
        </Dialog.CloseTrigger>
      </Dialog.Content>
    </Dialog.Positioner>
  </Portal>
</Dialog.Root>;
```

### 6. Validar antes de terminar

Corrige cada hallazgo y vuelve a ejecutarlo hasta que la lista quede vacía.

```
validate_usage({ code: "…", framework: "react" })
→ { findings: [] }
```

```json
{
  "ruleId": "moderno/no-hardcoded-color",
  "severity": "error",
  "message": "Hardcoded color \"#ff0000\" bypasses the token contract — components may only reference a contract slot.",
  "suggestion": "Reference a contract color slot instead, e.g. var(--background)."
}
```

## Reglas de validación

| Regla                                | Severidad | Detecta                                                                            |
| ------------------------------------ | --------- | ---------------------------------------------------------------------------------- |
| `moderno/no-hardcoded-color`         | error     | Literales hex, `rgb()`, `hsl()` y `oklch()`.                                       |
| `moderno/no-hardcoded-dimension`     | error     | Longitudes literales de `border-radius` y longitudes arbitrarias como `w-[320px]`. |
| `moderno/valid-props`                | error     | Props desconocidas y valores de enum inválidos.                                    |
| `moderno/no-raw-ark`                 | error     | Imports de `@ark-ui/*` o `@zag-js/*`.                                              |
| `moderno/valid-data-part-override`   | error     | Selectores `data-scope` / `data-part` que nombran una parte inexistente.           |
| `moderno/no-reimplemented-primitive` | warn      | Diálogos caseros, selects nativos y botones con variantes a mano.                  |

## Reglas de oro

- Nunca edites los componentes: tematízalos con variables CSS y varíalos con props.
- Referencia slots del contrato (`--background`, `--primary`, `--radius`, …), nunca colores hex, espaciados en px ni duraciones en ms.
- Pon los valores de marca en un tema, no en `@moderno-ui/tokens`.
- Mantén `:root` claro y `.dark` oscuro. No añadas un tercer mecanismo de tematización.
- Importa CSS solo desde `@moderno-ui/css`, nunca desde rutas internas.

## Lint en CI

[`@moderno-ui/lint`](https://www.npmjs.com/package/@moderno-ui/lint) ejecuta las mismas reglas que `validate_usage`, para personas y para CI.

```js
// eslint.config.js
import moderno from "@moderno-ui/lint";

export default [...moderno.configs.recommended];
```

```sh
npx moderno-lint src/**/*.tsx
```
