## Uso

<ForFramework fw="react">

```tsx
import { Verify } from "@/components/screens/verify";
```

```tsx
<Verify
  sentTo={email}
  resendIn={secondsLeft}
  resent={justResent}
  onSubmit={(event) => {
    event.preventDefault();
    const form = new FormData(event.currentTarget, event.nativeEvent.submitter);
    if (form.get("intent") === "resend") return resend(String(form.get("email")));
    return check(String(form.get("code")));
  }}
/>
```

## Referencia de API

### Props

Los callbacks son props `on…` en React y Solid, en minúsculas (`onsubmit`) en Svelte y eventos (`submit`, `navigate`) en Vue.

| Prop          | Tipo                     | Por defecto | Descripción                                                                           |
| ------------- | ------------------------ | ----------- | ------------------------------------------------------------------------------------- |
| `sentTo`      | `string`                 | `""`        | La dirección a la que fue el código; se nombra en la tarjeta y se envía como `email`. |
| `codeLength`  | `number`                 | `6`         | Número de celdas, y de dígitos que nombra la descripción.                             |
| `resendIn`    | `number`                 | `0`         | Segundos hasta poder pedir otro código; el temporizador es tuyo.                      |
| `resent`      | `boolean`                | `false`     | Acaba de salir un código nuevo: la cabecera de la tarjeta lo dice.                    |
| `error`       | `string`                 | —           | Fallo del formulario: demasiados intentos o una dirección ya verificada.              |
| `errors`      | `Record<string, string>` | —           | Mensajes por campo; aquí solo `code`.                                                 |
| `loading`     | `boolean`                | `false`     | Envío en curso: todos los controles inertes, el botón ocupado.                        |
| `disabled`    | `boolean`                | `false`     | Aquí no se puede comprobar un código; combínalo con `error`.                          |
| `onSubmit`    | `(event) => void`        | —           | Envío nativo del formulario, desde cualquiera de los dos botones.                     |
| `onNavigate`  | `(to, event) => void`    | —           | Se pulsó un enlace de la pantalla: `home`, `support`, `privacy` o `terms`.            |
| `signInHref`  | `string`                 | `"#"`       | Destino de «Sign in» en el pie de la tarjeta.                                         |
| `homeHref`    | `string`                 | `"#"`       | Destino del logotipo.                                                                 |
| `supportHref` | `string`                 | `"#"`       | Destino de «Contact support».                                                         |
| `privacyHref` | `string`                 | `"#"`       | Destino del enlace de privacidad.                                                     |
| `termsHref`   | `string`                 | `"#"`       | Destino del enlace de términos.                                                       |

### Estados

| Estado            | Props                | Qué se renderiza                                                       |
| ----------------- | -------------------- | ---------------------------------------------------------------------- |
| Por defecto       | —                    | Las celdas del código y el reenvío, listos.                            |
| Error de campo    | `errors={{ code }}`  | Todas las celdas inválidas, con el motivo debajo como `alert`.         |
| Reenvío bloqueado | `resendIn > 0`       | El reenvío deshabilitado y con el texto «Send a new code in 42s».      |
| Reenviado         | `resent`             | La cabecera dice que va un código nuevo y que el anterior ya no sirve. |
| Error             | `error` + `disabled` | Una alerta, el formulario inerte.                                      |
| Cargando          | `loading`            | Controles inertes, envío con `aria-busy`.                              |

### Campos del formulario

| Nombre   | Control            | Se envía                                   |
| -------- | ------------------ | ------------------------------------------ |
| `code`   | Campo oculto (Ark) | Siempre; las celdas no tienen nombre.      |
| `email`  | Campo oculto       | Cuando hay `sentTo`.                       |
| `intent` | Botón de reenvío   | Solo con el reenvío, con `value="resend"`. |

### Tamaño

| Paso del contenedor      | Cambio                            |
| ------------------------ | --------------------------------- |
| `@sm` (`--container-sm`) | La cabecera pasa a una sola fila. |
| `@md` (`--container-md`) | El pie pasa a una sola fila.      |

## Notas

- Los dos botones envían el mismo formulario; lee `new FormData(form, submitter)` para distinguir reenvío y comprobación.
- La comprobación va primero en el formulario, así que Enter siempre verifica.
- Cada celda lleva `autocomplete="one-time-code"`, así que el móvil puede ofrecer el código desde la notificación.
- Pegar un código rellena todas las celdas; el foco avanza al escribir y retrocede con Retroceso.
- La pantalla no lleva temporizador: descuenta `resendIn` en tu página.
- La dirección viaja en un campo oculto, así que ambos envíos funcionan antes de hidratar.
