La UI generativa deja que un agente responda con UI, no solo con texto. Pide "ventas del mes" y la respuesta es una tarjeta con un gráfico. Pide "confirma mi pedido" y es una tarjeta con botones. Di "hola" y es solo texto.

Úsala en un chat o en un panel de asistente, cuando un trozo de UI responde mejor que un párrafo. Por ahora es solo para React.

Cada turno tiene tres pasos:

1. Un **router** (un modelo System One, Jev o Nimble) elige la **superficie**: `text`, `widget`, `screen` o `dashboard`, y los componentes que ayudan.
2. Un **LLM** escribe la respuesta en OpenUI Lang, usando solo esos componentes.
3. `<GenUI>` dibuja la respuesta con `@moderno-ui/react`. Tu tema le da estilo, así que no necesita CSS propio.

## Instalación

<Install pkg="@moderno-ui/genui" />

Necesita React y el paquete de React de Moderno a su lado:

```sh
npm install react react-dom @moderno-ui/react @moderno-ui/css
```

OpenUI envía telemetría por defecto. Apágala donde instalas y donde corre el servidor:

```sh
OPENUI_TELEMETRY_DISABLED=1
```

## Uso

En el servidor, `generateUI` responde un mensaje. Emite trozos de texto y de OpenUI Lang.

```ts
import { generateUI } from "@moderno-ui/genui/server";
import manifest from "@moderno-ui/react/moderno.agent.json" with { type: "json" };
import contract from "@moderno-ui/css/moderno.agent.json" with { type: "json" };

const chunks = generateUI({
  message: "ventas del mes",
  judge: {
    baseUrl: "https://api.typesafe.ai",
    model: "jev-latest",
    apiKey: process.env.JEV_API_KEY,
  },
  llm, // tu LLM, mira "llm" más abajo
  manifest,
  contract,
});

for await (const chunk of chunks) {
  // Envía cada trozo a la página.
}
```

En la página, `<GenUI>` dibuja el OpenUI Lang que tiene hasta ahora.

```tsx
import { GenUI } from "@moderno-ui/genui/react";

<GenUI response={program} isStreaming={!done} />;
```

## Referencia de la API

### generateUI

`generateUI(options)` de `@moderno-ui/genui/server`. Pregunta al router, luego al LLM, y emite los trozos según llegan. Si el programa no es válido, pregunta otra vez al LLM con los errores. Si vuelve a fallar, responde con texto.

Un programa válido también tiene que ser usable. El prompt le da al LLM unas reglas de UI: elegir el control según el dato, un solo botón primario por formulario, etiquetas en el idioma del usuario, sin emojis. Luego un lint revisa el programa. Un `NumberInput` para un código, un `Select` sin opciones, un formulario sin exactamente un botón primario, o un botón primario con su propia acción cuentan como errores, así que activan el mismo reintento.

| Opción     | Tipo                 | Por defecto | Descripción                                                                 |
| ---------- | -------------------- | ----------- | --------------------------------------------------------------------------- |
| `message`  | `string`             | —           | El mensaje del usuario.                                                     |
| `context`  | `ChatMessage[]`      | `[]`        | Los turnos antes de `message`, del más antiguo al más nuevo.                |
| `judge`    | `JudgeConfig`        | —           | El servidor System One al que pregunta el router.                           |
| `llm`      | `LLM`                | —           | El modelo que escribe la respuesta.                                         |
| `manifest` | `ComponentsManifest` | —           | `@moderno-ui/react/moderno.agent.json`. El router elige de ahí.             |
| `contract` | `ContractManifest`   | —           | `@moderno-ui/css/moderno.agent.json`. Los espacios del layout salen de ahí. |

`ChatMessage` es `{ role: "user" | "assistant"; content: string }`.

Cada trozo es un `GenUIChunk`:

| Trozo                         | Qué hacer con él                                                     |
| ----------------------------- | -------------------------------------------------------------------- |
| `{ type: "text", text }`      | Muéstralo como texto del chat.                                       |
| `{ type: "program", text }`   | Añádelo al programa que pasas a `<GenUI>`.                           |
| `{ type: "discard", errors }` | Borra todo lo que este turno ha mostrado. Sigue una respuesta nueva. |

### route

`route(message, context, components, options)` es el router solo. `generateUI` lo llama por ti. `components` son los `components` del manifiesto. Devuelve `{ surface, components }`.

Hace dos llamadas a `judge`, diez preguntas en total. La primera pregunta la superficie y el tipo de UI (un gráfico, un formulario, una tarjeta de confirmación…). La segunda pregunta por los 8 componentes que mejor encajan con ese tipo.

| Opción          | Tipo          | Por defecto | Descripción                                                                                             |
| --------------- | ------------- | ----------- | ------------------------------------------------------------------------------------------------------- |
| `judge`         | `JudgeConfig` | —           | El servidor System One.                                                                                 |
| `threshold`     | `number`      | `0.5`       | Un componente se elige cuando su puntuación llega a este valor.                                         |
| `minConfidence` | `number`      | `0.5`       | Si la confianza es menor, una superficie `text` se trata como UI. El LLM aún puede responder con texto. |
| `shortlist`     | `number`      | `8`         | Por cuántos componentes pregunta la segunda llamada.                                                    |

Si ningún componente pasa el umbral, se quedan todos.

### judge

`JudgeConfig` dice qué servidor System One enruta el mensaje. Jev en TypeSafe y Nimble en Ollama hablan la misma API (`POST /v1/systemone`), así que solo cambia la configuración.

| Campo       | Tipo     | Por defecto | Descripción                                                   |
| ----------- | -------- | ----------- | ------------------------------------------------------------- |
| `baseUrl`   | `string` | —           | La URL del servidor.                                          |
| `model`     | `string` | —           | `jev-latest` o `nimble`.                                      |
| `apiKey`    | `string` | —           | Se envía como `Authorization: Bearer`. Ollama no la necesita. |
| `retries`   | `number` | `3`         | Reintentos tras un 429 o un 529.                              |
| `backoffMs` | `number` | `500`       | La primera espera entre reintentos. Se dobla cada vez.        |

Jev en TypeSafe:

```ts
const judge = {
  baseUrl: "https://api.typesafe.ai",
  model: "jev-latest",
  apiKey: process.env.JEV_API_KEY,
};
```

Nimble en un Ollama local (0.35 o posterior, tras `ollama pull nimble`):

```ts
const judge = { baseUrl: "http://localhost:11434", model: "nimble" };
```

Una petición rechazada lanza un `SystemOneError` con su `status` y su `body`.

### llm

`LLM` es una función: recibe el prompt de sistema y los mensajes, y emite la respuesta como texto. Tú eliges el proveedor. Este, del playground, llama a OpenRouter:

```ts
import type { LLM } from "@moderno-ui/genui/server";

export function openRouterLLM(apiKey: string, model: string): LLM {
  return async function* (system, messages) {
    const response = await fetch("https://openrouter.ai/api/v1/chat/completions", {
      method: "POST",
      headers: { Authorization: `Bearer ${apiKey}`, "Content-Type": "application/json" },
      body: JSON.stringify({
        model,
        stream: true,
        messages: [{ role: "system", content: system }, ...messages],
      }),
    });
    if (!response.ok || !response.body)
      throw new Error(`OpenRouter failed with ${response.status}`);
    yield* contentDeltas(response.body); // cada `choices[0].delta.content` del stream SSE
  };
}
```

El adaptador completo, con `contentDeltas`, está en `packages/genui/playground/server/openrouter.ts`.

### fromManifest

`fromManifest(manifest, contract)` convierte `moderno.agent.json` en componentes de OpenUI: uno por cada componente y parte de Moderno, más los layouts `Stack` y `Grid`. Lee los componentes reales, así que la lista nunca se desvía de ellos.

Un componente de formulario, como `Select`, `NumberInput` o `Field`, llega como una sola **forma simple** con argumentos planos en vez de sus partes: `Select("Talla", ["Pequeña", "Grande"])`. `<GenUI>` dibuja el componente completo a partir de ellos, así que el LLM no puede equivocarse en su estructura. Los overlays, los toasts y los layouts de la app, como `Dialog`, `Toast` y `Splitter`, quedan fuera: no tienen lugar dentro de una respuesta.

El LLM no puede fijar `size`: cada control de un widget se dibuja en `md`, así que todos tienen la misma altura. Cada descripción dice también cuándo no usar el componente y qué usar en su lugar.

### createSubLibrary

`createSubLibrary(components, names)` deja solo los componentes nombrados, las partes que contienen y los layouts. El prompt del LLM lista menos componentes, así que es más corto, más rápido y más barato. `generateUI` lo llama con lo que eligió el router.

### GenUI

`<GenUI>` de `@moderno-ui/genui/react` dibuja un programa de OpenUI Lang con `@moderno-ui/react`.

| Prop          | Tipo                              | Por defecto | Descripción                                                                                                                               |
| ------------- | --------------------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `response`    | `string \| null`                  | —           | El programa hasta ahora. `null` no dibuja nada.                                                                                           |
| `isStreaming` | `boolean`                         | `false`     | Verdadero mientras el programa sigue llegando.                                                                                            |
| `onAction`    | `(event: ActionEvent) => void`    | —           | Un componente lanzó una acción, como el `@ToAssistant` de un botón. Un botón sin acción envía su etiqueta con los valores del formulario. |
| `onError`     | `(errors: OpenUIError[]) => void` | —           | El programa terminado tiene errores, como un componente que no se pudo dibujar. Reintenta o responde en texto. `[]` limpia.               |
