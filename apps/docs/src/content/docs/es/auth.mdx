## Uso

<ForFramework fw="react">

```tsx

```

## Referencia de API

### Props

Los callbacks son props `on…` en React y Solid, en minúsculas (`onstepchange`) en Svelte y eventos (`stepChange`, `authenticated`) en Vue.

| Prop              | Tipo               | Por defecto      | Descripción                                                            |
| ----------------- | ------------------ | ---------------- | ---------------------------------------------------------------------- |
| `initialStep`     | `AuthStep`         | `"sign-in"`      | La pantalla con la que abre el flujo; en una app, lo que diga la ruta. |
| `initialEmail`    | `string`           | `""`             | Una dirección ya conocida, llevada entre pasos.                        |
| `resetToken`      | `string`           | `""`             | El token de un enlace de recuperación, al entrar por `reset-password`. |
| `resendSeconds`   | `number`           | `30`             | Cuánto sigue bloqueado el reenvío de verify tras salir un código.      |
| `codeLength`      | `number`           | `6`              | Dígitos del código de un solo uso.                                     |
| `hrefFor`         | `(step) => string` | `` `#${step}` `` | La URL de cada paso; guía tanto los enlaces como la intercepción.      |
| `onStepChange`    | `(step) => void`   | —                | El flujo se movió; refléjalo en la URL.                                |
| `onAuthenticated` | `(email) => void`  | —                | La persona ya entró: sesión iniciada, verificada o restablecida.       |
| `homeHref`        | `string`           | `"#"`            | Destino del logotipo en todas las pantallas.                           |
| `supportHref`     | `string`           | `"#"`            | Destino de «Contact support» en todas las pantallas.                   |
| `privacyHref`     | `string`           | `"#"`            | Destino de los enlaces de privacidad en todas las pantallas.           |
| `termsHref`       | `string`           | `"#"`            | Destino de los enlaces de términos en todas las pantallas.             |

### Pasos

`AuthStep` es una de las cinco pantallas, en el orden en que el flujo las recorre.

| Paso                                      | Se llega por                                       | Sale hacia                                |
| ----------------------------------------- | -------------------------------------------------- | ----------------------------------------- |
| [`sign-in`](/es/sign-in/)                 | El primer paso, o «Sign in» desde cualquier sitio  | `onAuthenticated`, o sus dos enlaces      |
| [`sign-up`](/es/sign-up/)                 | «Create an account»                                | `verify`, al enviar                       |
| [`forgot-password`](/es/forgot-password/) | «Forgot your password?»                            | Su propia confirmación, y luego el correo |
| [`reset-password`](/es/reset-password/)   | El enlace del correo: `initialStep` + `resetToken` | `onAuthenticated`, al enviar              |
| [`verify`](/es/verify/)                   | Un registro enviado                                | `onAuthenticated`, con el código completo |

### Estado

Lo que guarda el ensamblaje para que las pantallas no tengan que hacerlo.

| Estado            | Guarda                                                                |
| ----------------- | --------------------------------------------------------------------- |
| `step`            | La pantalla que está ahora en la ruta.                                |
| `email`           | La dirección, desde donde se escribió hasta donde se nombra después.  |
| `token`           | El secreto del enlace de recuperación del correo.                     |
| `resendIn`        | Los segundos que quedan del reenvío; el único temporizador del flujo. |
| `sent` / `resent` | Las confirmaciones tras salir un enlace de recuperación o un código.  |
| `errors`          | Lo que rechazó el último envío.                                       |

## Notas

- El ensamblaje es código de ejemplo, el único archivo que se espera que reescribas. Las pantallas quedan como se publicaron.
- La navegación intercepta `href` reales: solo clics izquierdos simples; los modificados y los de rueda van al navegador.
- Los avances son envíos de formulario normales, leídos con `new FormData(form, submitter)`.
- `sent`, `resent` y `errors` se reinician en cada movimiento.
- El aviso «Open the reset link» existe solo porque el ejemplo no tiene servidor de correo. Bórralo.
- `onAuthenticated` devuelve el flujo al primer paso y no pinta página de éxito; salir es trabajo de tu router.
