The flow lands in `src/components/flows/`, its five screens in `screens/` and their shared block in `blocks/`, each versioned on its own.

## Usage

<ForFramework fw="react">

```tsx
import { AuthFlow } from "@/components/flows/auth-flow";
```

```tsx
<AuthFlow
  hrefFor={(step) => `/auth/${step}`}
  initialStep={stepFromUrl}
  onStepChange={(step) => router.push(`/auth/${step}`)}
  onAuthenticated={() => router.push("/")}
/>
```

## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onstepchange`) in Svelte, and emits (`stepChange`, `authenticated`) in Vue.

| Prop              | Type               | Default          | Description                                                              |
| ----------------- | ------------------ | ---------------- | ------------------------------------------------------------------------ |
| `initialStep`     | `AuthStep`         | `"sign-in"`      | The screen the flow opens on; in an app, whatever the route says.        |
| `initialEmail`    | `string`           | `""`             | An address already known, carried between steps.                         |
| `resetToken`      | `string`           | `""`             | The token from an emailed reset link, when entering at `reset-password`. |
| `resendSeconds`   | `number`           | `30`             | How long the verify resend stays locked after a code goes out.           |
| `codeLength`      | `number`           | `6`              | Digits in the one-time code.                                             |
| `hrefFor`         | `(step) => string` | `` `#${step}` `` | The URL of each step; drives both the links and the interception.        |
| `onStepChange`    | `(step) => void`   | —                | The flow moved; mirror it in the URL.                                    |
| `onAuthenticated` | `(email) => void`  | —                | The reader is through: signed in, verified or reset.                     |
| `homeHref`        | `string`           | `"#"`            | Target of the wordmark on every screen.                                  |
| `supportHref`     | `string`           | `"#"`            | Target of "Contact support" on every screen.                             |
| `privacyHref`     | `string`           | `"#"`            | Target of the privacy links on every screen.                             |
| `termsHref`       | `string`           | `"#"`            | Target of the terms links on every screen.                               |

### Steps

`AuthStep` is one of the five screens, in the order the flow moves through them.

| Step                                      | Reached by                                     | Leaves for                              |
| ----------------------------------------- | ---------------------------------------------- | --------------------------------------- |
| [`sign-in`](/en/sign-in/)                 | The first step, or "Sign in" from anywhere     | `onAuthenticated`, or its two links out |
| [`sign-up`](/en/sign-up/)                 | "Create an account"                            | `verify`, on submit                     |
| [`forgot-password`](/en/forgot-password/) | "Forgot your password?"                        | Its own confirmation, then the email    |
| [`reset-password`](/en/reset-password/)   | The emailed link: `initialStep` + `resetToken` | `onAuthenticated`, on submit            |
| [`verify`](/en/verify/)                   | A submitted sign-up                            | `onAuthenticated`, on a full code       |

### State

What the assembly holds so the screens don't have to.

| State             | Holds                                                              |
| ----------------- | ------------------------------------------------------------------ |
| `step`            | The screen currently on the route.                                 |
| `email`           | The address, carried from where it was typed to where it is named. |
| `token`           | The secret from the emailed reset link.                            |
| `resendIn`        | Seconds left on the verify resend; the only timer in the flow.     |
| `sent` / `resent` | The confirmations after a recovery link or a new code goes out.    |
| `errors`          | Whatever the last submit rejected.                                 |

## Notes

- The assembly is example code, the one file you are expected to rewrite. The screens stay as shipped.
- Navigation intercepts real `href`s: plain left clicks only; modified and middle clicks go to the browser.
- Forward moves are plain form submissions, read with `new FormData(form, submitter)`.
- `sent`, `resent` and `errors` reset on every move.
- The "Open the reset link" banner exists only because the example has no mail server. Delete it.
- `onAuthenticated` returns the flow to its first step and draws no success page; leaving is your router's job.
