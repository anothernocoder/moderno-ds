agent:
  intent: A settings form laid out as titled groups of related fields with one actions row.
  whenToUse: "Any form long enough to need sections: account or workspace settings, a profile editor, a billing or notification panel, the body of a multi-field create dialog."
  whenNotToUse:
    - case: A sign-in or sign-up form
      use: LoginForm, which composes the credential fields inside a Card
    - case: One or two fields with no grouping to do
      use: Field and Button directly — a form layout with a single group is just overhead
    - case: A list of records with per-row actions
      use: a list block; this block collects input, it does not display a collection
  gotchas:
    - "Presentational: it holds no values and issues no request. The controls are uncontrolled — read the form in your submit handler, or swap in your form library's bindings once the file is yours."
    - "`errors` is keyed by the field's `name` (`fullName`, `email`, `about`), so renaming a field means renaming its key."
    - "`error` and `errors` are independent: the form-level alert says the save failed, the field messages say why. Passing only `errors` marks the fields without raising an alert."
    - "`loading` implies inert: every control and both actions are disabled and the submit carries aria-busy, so a second save cannot be fired mid-request."
    - "The block responds to its container, never the viewport, and uses all three steps. Mount it narrow and the actions row stacks, the fields run one-up and the group headings sit above their fields."
    - "It is a block, so you own the copy: the groups, the fields, the labels and the helper text are yours to edit after `moderno add`."
  theming:
    - "Nothing is painted here. The controls are Field and Checkbox, the group rules are Divider, the actions are Button's primary and secondary variants, and the failure is Alert's error variant."
    - "Layout comes from the Tailwind preset's contract-backed utilities; the three steps are --container-sm, --container-md and --container-lg."
    - "The form sits on --background and inherits --foreground: it is a page section, not a surface, so a theme's canvas shows through it."

## API Reference

### Props

| Prop       | Type                     | Default | Description                                                      |
| ---------- | ------------------------ | ------- | ---------------------------------------------------------------- |
| `error`    | `string`                 | —       | Form-level alert above the first group.                          |
| `errors`   | `Record<string, string>` | —       | Per-field messages keyed by field `name`; each marks it invalid. |
| `loading`  | `boolean`                | `false` | Disables every control and marks the submit `aria-busy`.         |
| `disabled` | `boolean`                | `false` | The form is read-only.                                           |
| `onSubmit` | `(event) => void`        | —       | Native submit event. Svelte: `onsubmit`. Vue: `@submit`.         |
| `onCancel` | `() => void`             | —       | The "Cancel" button. Svelte: `oncancel`. Vue: `@cancel`.         |

### Fields

| Group         | Field           | `name`           |
| ------------- | --------------- | ---------------- |
| Profile       | Full name       | `fullName`       |
| Profile       | Email           | `email`          |
| Profile       | About           | `about`          |
| Notifications | Product updates | `productUpdates` |
| Notifications | Security alerts | `securityAlerts` |

### States

| State        | Prop       | What renders                                                         |
| ------------ | ---------- | -------------------------------------------------------------------- |
| Default      | —          | The empty form with placeholders and helper text.                    |
| Error        | `error`    | One form-level alert for the save.                                   |
| Field errors | `errors`   | Each named field goes invalid and prints its own message.            |
| Loading      | `loading`  | Every control and both actions disabled; the submit shows a spinner. |
| Disabled     | `disabled` | Every control and both actions disabled.                             |

### Sizing

| Container step           | What changes                                          |
| ------------------------ | ----------------------------------------------------- |
| `@sm` (`--container-sm`) | The actions row stops stacking and aligns to the end. |
| `@md` (`--container-md`) | The fields pair off two per row.                      |
| `@lg` (`--container-lg`) | Each group heading moves beside its fields.           |

## Notes

- Presentational: the controls are uncontrolled and it sends no request. Read the form in your submit handler.
- `error` and `errors` are independent. Passing only `errors` marks the fields without an alert.
- For credentials, use [Login form](/en/login-form/) instead.
