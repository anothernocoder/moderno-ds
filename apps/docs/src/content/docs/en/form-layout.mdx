**Form layout** is the shape every settings page ends up needing: related fields
gathered into a titled group with a sentence explaining it, groups separated by a
rule, and one actions row that commits the whole thing. It composes `Field`,
`Checkbox`, `Divider`, `Button` and `Alert` and paints nothing of its own, so a
theme re-skins it untouched.

It is a _block_, not a screen: it does not own the viewport and holds no values.
The example ships an account-settings form because a block has to be something
concrete — the groups, the fields and the copy are yours to rewrite the moment
`moderno add` copies the file.

## Installation

<Install item="form-layout" />

Installing a block copies its file into your project and records it in
`.moderno/manifest.json` under its own version, so `moderno update` and
`moderno diff` keep working per item. From that moment the file is yours.

## Sizing

This is the block that leans hardest on the container-query policy, because a
form changes shape three times as it is given room — and each change is a
different decision:

| Step  | Slot             | What changes                                                            |
| ----- | ---------------- | ----------------------------------------------------------------------- |
| `@sm` | `--container-sm` | The actions row stops stacking and lines up to the trailing edge.       |
| `@md` | `--container-md` | The field grid goes one-up → two-up, so short fields pair off.          |
| `@lg` | `--container-lg` | Each group's heading leaves the top of its fields and sits beside them. |

None of that reads the window. The same file is correct in a 320px settings
sidebar, in a 480px panel, in the page column and on a 50rem stage, in light and
dark alike, without a single media query — which is why the preview above mounts
it at four widths at once and they disagree with each other on one screen. The
rules behind this are in [Blocks and containers](/en/blocks-and-containers/) and
ADR-0005.

## States

| State           | What renders                                                                                                                             |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Default / empty | The pristine form — placeholders and helper text, no values. A form is the input surface, so "nothing entered yet" is its resting state. |
| Hover           | The controls' own affordances from `components.css`: the field borders raise to `--ring`, the buttons lift a step.                       |
| Focus visible   | The shared 2px `--ring` outline on every control and on both actions; an invalid field keeps the destructive colour while focused.       |
| Disabled        | `disabled` — the form is read-only (a viewer-role member, a locked account). Controls take the muted fill.                               |
| Loading         | `loading` — every control and both actions inert, the submit `aria-busy` with a spinner that stops under `prefers-reduced-motion`.       |
| Error           | `error` raises one form-level `Alert`; each key in `errors` marks that field invalid and prints its own `Field.ErrorText`.               |

Unlike [Login form](/en/login-form/), which must never say _which_ credential was
wrong, this block names the field. The person editing a settings form already
owns the account, so there is nothing to leak, and "Enter a valid email address"
next to the box is the only message they can act on.

## Props

| Prop       | Type                     | Default | What it does                                                                                 |
| ---------- | ------------------------ | ------- | -------------------------------------------------------------------------------------------- |
| `error`    | `string`                 | —       | Form-level failure message; renders the alert above the first group.                         |
| `errors`   | `Record<string, string>` | —       | Per-field messages keyed by the field's `name`; each marks that field invalid.               |
| `loading`  | `boolean`                | `false` | The save is in flight: controls inert, submit busy.                                          |
| `disabled` | `boolean`                | `false` | The form is read-only.                                                                       |
| `onSubmit` | submit handler           | —       | The native submit event. React/Solid take `onSubmit`, Svelte `onsubmit`, Vue emits `submit`. |
| `onCancel` | handler                  | —       | The trailing "Cancel". React/Solid take `onCancel`, Svelte `oncancel`, Vue emits `cancel`.   |
