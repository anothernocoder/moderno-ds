agent:
  intent: The full-viewport sign-up screen — one state of the auth flow, presentational.
  whenToUse: "The route a new person lands on: /signup, /register, the destination of a 'Create an account' link or an invite email."
  whenNotToUse:
    - case: A sign-up section inside a page you already own (a modal, a marketing page's hero)
      use: the LoginForm block with mode="sign-up" — a block never owns the viewport
    - case: The returning person
      use: the SignIn screen, which mounts the same card in its other mode
    - case: The whole auth journey, with the navigation between its steps
      use: the auth flow, which sequences this screen with sign-in, forgot-password, reset-password and verify
    - case: Profile questions asked after the account exists (role, team size, avatar)
      use: the profile-setup screen — this screen asks only what an account cannot be created without
  gotchas:
    - "Presentational: no credentials, no request, no router. `onSubmit` hands back the native event and `onNavigate` names the destination of every link the screen draws itself and hands back the click event with it, so a router can `preventDefault()`."
    - "`error` and `errors` are different failures: `error` is the form-level alert (the account could not be created at all, the consent box is unticked), `errors` is keyed by the field's `name` (`fullName`, `email`, `password`) and marks those fields. A sign-up may name the field it rejected; a sign-in may not."
    - "The card's own links — sign-in, terms, privacy — are `href`s, not callbacks: the legal text a person is being asked to agree to has to be reachable when hydration fails, or the consent is not informed. Pass `signInHref`, `termsHref` and `privacyHref`."
    - "`highlights={[]}` is the screen's empty state: the aside is not rendered at all and the card sits centred and alone, which is what an invite-only or internal sign-up looks like."
    - "Full-viewport is a height (`min-h-dvh`). Every width decision is read off the screen's own container, so it is still correct mounted in a pane that is not the window."
    - "The screen imports its block from `@/components/blocks/…`, where `moderno add` puts it. If your project uses a different path alias, that import line is the only thing to change."
    - "The root is a `<div>`, not a `<main>` — most app shells already provide the `main` landmark, and two visible ones in a document is invalid. If your route has none, change that one element."
  theming:
    - "Nothing is painted here. The card is the LoginForm block; the screen's own chrome is `text-foreground` / `text-muted-foreground` on `bg-background`, and the highlights are ruled off with `border-border`."
    - "Layout comes from the Tailwind preset's contract-backed utilities; the three steps are --container-sm, --container-md and --container-lg."
    - "The default highlights are a prop, not a hardcoded pitch: pass your own three, or `[]` to drop the column."

## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onsubmit`) in Svelte, and emits (`submit`, `navigate`) in Vue.

| Prop          | Type                     | Default       | Description                                                                      |
| ------------- | ------------------------ | ------------- | -------------------------------------------------------------------------------- |
| `error`       | `string`                 | —             | The account could not be created: shows the form alert.                          |
| `errors`      | `Record<string, string>` | —             | Per-field messages keyed by `fullName`, `email` or `password`.                   |
| `loading`     | `boolean`                | `false`       | Submit in flight: every control inert, the button busy.                          |
| `disabled`    | `boolean`                | `false`       | Sign-up is unavailable (closed beta, invite-only workspace).                     |
| `highlights`  | `SignUpHighlight[]`      | three samples | Reasons beside the form, as `{ id, title, description? }`. `[]` hides the aside. |
| `onSubmit`    | `(event) => void`        | —             | Native form submit.                                                              |
| `onNavigate`  | `(to, event) => void`    | —             | A screen link was clicked: `home`, `signIn`, `privacy` or `terms`.               |
| `signInHref`  | `string`                 | `"#"`         | Target of "Sign in", in the masthead and the card footer.                        |
| `homeHref`    | `string`                 | `"#"`         | Target of the wordmark.                                                          |
| `privacyHref` | `string`                 | `"#"`         | Target of the privacy links.                                                     |
| `termsHref`   | `string`                 | `"#"`         | Target of the terms links.                                                       |

### States

| State        | Props             | Renders                                          |
| ------------ | ----------------- | ------------------------------------------------ |
| Default      | —                 | The card with the highlights beside or under it. |
| Error        | `error`           | One form alert; no field is marked.              |
| Field errors | `errors`          | Each named field invalid, with its own message.  |
| Loading      | `loading`         | Controls inert, submit `aria-busy`.              |
| Disabled     | `disabled`        | The form is shown but can't be used.             |
| Empty        | `highlights={[]}` | No aside; the card sits centred and alone.       |

### Form fields

| Name       | Control  | Posted                                        |
| ---------- | -------- | --------------------------------------------- |
| `fullName` | Text     | Always.                                       |
| `email`    | Email    | Always.                                       |
| `password` | Password | Always, marked `autocomplete="new-password"`. |
| `terms`    | Checkbox | Required; posted when ticked.                 |

### Sizing

| Container step           | Change                               |
| ------------------------ | ------------------------------------ |
| `@sm` (`--container-sm`) | The masthead moves onto one row.     |
| `@md` (`--container-md`) | The footer moves onto one row.       |
| `@lg` (`--container-lg`) | The highlights move beside the card. |

### Composition

| Part                         | Role                                                           |
| ---------------------------- | -------------------------------------------------------------- |
| [LoginForm](/en/login-form/) | The credential card, in `sign-up` mode, with `titleLevel={1}`. |
| Highlights aside             | Drawn by the screen itself, headed "What you get on day one".  |

## Notes

- Presentational: no request, no router, no account logic. The page that mounts it owns them.
- The sign-in, terms and privacy links are plain `href`s, so the legal text opens before the page hydrates.
- Unlike sign-in, a sign-up may name the field it rejected through `errors`.
- `onNavigate` passes the click event: skip `metaKey`/`ctrlKey` clicks, then `preventDefault()` to route.
- The root is a `<div>`, not a `<main>`. Make it your `<main>` if the route has none.
- The screen imports its block from `@/components/blocks/…`; edit that line if your alias differs.
