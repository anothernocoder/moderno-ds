  whenToUse: "The route a locked-out person lands on: /forgot-password, /recover, the destination of a 'Forgot your password?' link."
  whenNotToUse:
    - case: Setting the new password from the emailed link
      use: the reset-password screen — this one only asks for the address and confirms
    - case: A recovery form inside a page you already own (a modal, a re-auth step)
      use: the LoginForm block with mode="forgot-password" — a block never owns the viewport
    - case: The returning person who knows their password
      use: the SignIn screen, which mounts the same card in its other mode
    - case: The whole auth journey, with the navigation between its steps
      use: the auth flow, which sequences this screen with sign-in, sign-up, reset-password and verify
  gotchas:
    - "`sent` is the screen's second state, and it is not held here: pass it in after the request resolves. Unsent the card asks for the address, sent the same card confirms — nothing around it moves."
    - "It never says whether the address has an account. The confirmation reads 'if that address has an account' and renders the same either way; the code behind `onSubmit` must answer with the same response and the same timing for every address, or the screen is an account-enumeration endpoint with a friendly face."
    - "One `onSubmit` serves the request and the resend: the sent card resubmits the address from a hidden input, so 'Send it again' works with no JavaScript on the page."
    - "`error` is the form-level failure (the mail could not be sent, the address was asked for too often); `errors.email` marks a malformed address, which leaks nothing."
    - "`notices={[]}` is the screen's empty state: the aside is not rendered at all and the card sits centred and alone."
    - "The card's 'Sign in' link is an `href`, not a callback — someone here is already locked out, and a way back that needs hydration is no way back. Pass `signInHref`."
    - "Full-viewport is a height (`min-h-dvh`). Every width decision is read off the screen's own container, so it is still correct mounted in a pane that is not the window."
    - "The root is a `<div>`, not a `<main>` — most app shells already provide the `main` landmark, and two visible ones in a document is invalid."
    - "The page's `h1` is the card's own title: the screen hands the block `titleLevel={1}` rather than printing a heading of its own above it, so the outline is the card and then the notes' `h2`, with no rank skipped."
    - "The confirmation is announced as well as shown — the card's header is a live region, because `sent` rewrites it where it stands and nothing else moves to signal it."
  theming:
    - "Nothing is painted here. The card is the LoginForm block and the notes are the AlertList block; the screen's own chrome is `text-foreground` / `text-muted-foreground` on `bg-background`."
    - "Layout comes from the Tailwind preset's contract-backed utilities; the three steps are --container-sm, --container-md and --container-lg."
    - "The default notes are a prop, not a hardcoded FAQ: pass your own, or `[]` to drop the column."

## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onsubmit`) in Svelte, and emits (`submit`, `navigate`) in Vue.

| Prop               | Type                     | Default       | Description                                                          |
| ------------------ | ------------------------ | ------------- | -------------------------------------------------------------------- |
| `sent`             | `boolean`                | `false`       | The link has gone out: the card confirms instead of asking.          |
| `sentTo`           | `string`                 | `""`          | The address named in the confirmation and resent by "Send it again". |
| `error`            | `string`                 | —             | The link could not be sent: shows the form alert.                    |
| `errors`           | `Record<string, string>` | —             | Per-field messages; here only `email`.                               |
| `loading`          | `boolean`                | `false`       | Submit in flight: every control inert, the button busy.              |
| `disabled`         | `boolean`                | `false`       | Recovery is unavailable (SSO-only workspace, locked account).        |
| `notices`          | `AlertListItem[]`        | three samples | Notes beside the card. `[]` hides the aside.                         |
| `noticesError`     | `string`                 | —             | The notes failed to load; this message replaces the list.            |
| `noticesLoading`   | `boolean`                | `false`       | A busy region stands in for the notes.                               |
| `onSubmit`         | `(event) => void`        | —             | Native form submit, for both the request and the resend.             |
| `onNavigate`       | `(to, event) => void`    | —             | A screen link was clicked: `home`, `support`, `privacy` or `terms`.  |
| `onNoticeAction`   | `(id) => void`           | —             | A note's action button, with the note id.                            |
| `onDismissNotice`  | `(id) => void`           | —             | One note was dismissed.                                              |
| `onDismissNotices` | `() => void`             | —             | All notes were dismissed.                                            |
| `onRetryNotices`   | `() => void`             | —             | Retry after `noticesError`.                                          |
| `signInHref`       | `string`                 | `"#"`         | Target of "Sign in" in the card footer.                              |
| `homeHref`         | `string`                 | `"#"`         | Target of the wordmark.                                              |
| `supportHref`      | `string`                 | `"#"`         | Target of "Contact support".                                         |
| `privacyHref`      | `string`                 | `"#"`         | Target of the privacy link.                                          |
| `termsHref`        | `string`                 | `"#"`         | Target of the terms link.                                            |

### States

| State         | Props                | Renders                                                            |
| ------------- | -------------------- | ------------------------------------------------------------------ |
| Default       | —                    | The card asking for an address, with the notes beside or under it. |
| Sent          | `sent`, `sentTo`     | The same card, confirming in place; nothing around it moves.       |
| Error         | `error`              | One form alert.                                                    |
| Field error   | `errors={{ email }}` | The address field invalid, with its own message.                   |
| Loading       | `loading`            | Controls inert, submit `aria-busy`.                                |
| Disabled      | `disabled`           | The form is shown but can't be used.                               |
| Notes loading | `noticesLoading`     | A busy region in place of the notes.                               |
| Notes error   | `noticesError`       | An alert in place of the notes.                                    |
| Empty         | `notices={[]}`       | No aside; the card sits centred and alone.                         |

### Form fields

| Name    | Control      | Posted                                          |
| ------- | ------------ | ----------------------------------------------- |
| `email` | Email        | Before `sent`.                                  |
| `email` | Hidden input | After `sent`, carrying `sentTo` for the resend. |

### Sizing

| Container step           | Change                           |
| ------------------------ | -------------------------------- |
| `@sm` (`--container-sm`) | The masthead moves onto one row. |
| `@md` (`--container-md`) | The footer moves onto one row.   |
| `@lg` (`--container-lg`) | The notes move beside the card.  |

### Composition

| Part                         | Role                                                        |
| ---------------------------- | ----------------------------------------------------------- |
| [LoginForm](/en/login-form/) | The card, in `forgot-password` mode, with `titleLevel={1}`. |
| [AlertList](/en/alert-list/) | The notes, headed "About the reset link".                   |

## Notes

- The confirmation says "If … has an account, a link … is on its way" whether or not one exists.
- Your `onSubmit` must answer with the same response and timing for every address; rate-limit it.
- `errors.email` is only for a malformed address, never for an unknown one.
- The card header is a `status` live region, so the switch to `sent` is announced.
- The sent card carries the address in a hidden input, so "Send it again" works before hydration.
- Presentational: `sent` lives in your page, and one `onSubmit` handles both the request and the resend.
