Use it to start a whole checkout at once: cart, shipping, payment, review and confirmation. Walk it above: press Checkout, fill each form and place the order.

## Installation

<Install item="checkout" />

The flow lands in `src/components/flows/`, its five screens in `screens/` and their blocks in `blocks/`, each versioned on its own.

## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onorderplaced`) in Svelte, and emits (`stepChange`, `orderPlaced`, `continueShopping`) in Vue.

| Prop                 | Type                       | Default            | Description                                                       |
| -------------------- | -------------------------- | ------------------ | ----------------------------------------------------------------- |
| `initialStep`        | `CheckoutStep`             | `"cart"`           | The screen the flow opens on; in an app, whatever the route says. |
| `initialLines`       | `CheckoutLine[]`           | a sample cart      | The lines in the cart when the flow opens.                        |
| `deliveryOptions`    | `CheckoutDeliveryOption[]` | standard, express  | The ways the order can travel, priced as numbers.                 |
| `formatPrice`        | `(amount) => string`       | `` `€${amount}` `` | How an amount reads on screen.                                    |
| `hrefFor`            | `(step) => string`         | `` `#${step}` ``   | The URL of each step; used for the "Edit cart" links.             |
| `onStepChange`       | `(step) => void`           | —                  | The flow moved; mirror it in the URL.                             |
| `onOrderPlaced`      | `(order) => void`          | —                  | "Place order" went through on the review.                         |
| `onContinueShopping` | `() => void`               | —                  | "Continue shopping" was pressed on the confirmation.              |
| `homeHref`           | `string`                   | `"#"`              | Target of the wordmark on every screen.                           |
| `shopHref`           | `string`                   | `"#"`              | Target of "Continue shopping" in the cart's masthead.             |
| `helpHref`           | `string`                   | `"#"`              | Target of "Need help?" on shipping.                               |
| `ordersHref`         | `string`                   | `"#"`              | Target of "Your orders" on the confirmation.                      |
| `privacyHref`        | `string`                   | `"#"`              | Target of the privacy link on every screen.                       |
| `termsHref`          | `string`                   | `"#"`              | Target of the terms link on every screen.                         |

### Types

| Type                     | Fields                                                                          |
| ------------------------ | ------------------------------------------------------------------------------- |
| `CheckoutLine`           | `id`, `name`, `unitPrice`, `quantity`, and optional `options`, `href`, `image`. |
| `CheckoutDeliveryOption` | `id`, `label`, `description`, `price`.                                          |
| `CheckoutOrder`          | `number`, `email`, `lines`, `delivery`, `total`: what `onOrderPlaced` receives. |

### Steps

`CheckoutStep` is one of the five screens, in the order the flow moves through them.

| Step                                | Reached by                                             | Leaves for                                         |
| ----------------------------------- | ------------------------------------------------------ | -------------------------------------------------- |
| [`cart`](/en/cart/)                 | The first step, Back, "Edit cart" or Continue shopping | `shipping`, on Checkout                            |
| [`shipping`](/en/shipping/)         | Checkout, "Back to shipping", or a Change              | `payment`, on a full form; `cart`, on Back         |
| [`payment`](/en/payment/)           | A saved address, "Back to payment", or a Change        | `review`, on a full form; `shipping`, on Back      |
| [`review`](/en/review/)             | A saved card                                           | `confirmation`, on Place order; `payment`, on Back |
| [`confirmation`](/en/confirmation/) | A placed order                                         | `cart`, on Continue shopping                       |

### State

What the assembly holds so the screens don't have to.

| State             | Holds                                                   |
| ----------------- | ------------------------------------------------------- |
| `step`            | The screen currently on the route.                      |
| `lines`           | The cart: every quantity change and removal lands here. |
| `shippingDetails` | The contact and address from the shipping form.         |
| `deliveryId`      | The delivery method chosen on shipping.                 |
| `cardEnding`      | The last four digits of the card, for the review.       |
| `order`           | The placed order the confirmation shows.                |
| `errors`          | The fields the last submit left empty.                  |

## Notes

- The assembly is example code, the one file you are expected to rewrite. The screens stay as shipped.
- Prices are numbers in the assembly and text on screen; `formatPrice` joins them.
- The shipping and payment forms are only checked for empty fields. Put your requests in `saveAddress` and `saveCard`.
- The checkout-form block takes no values, so a form you step back to starts empty.
- "Edit cart" is a real `href`: plain left clicks move the flow, modified clicks go to the browser.
- Placing the order empties the cart. `#MD-10482` stands in for your server's order number.
