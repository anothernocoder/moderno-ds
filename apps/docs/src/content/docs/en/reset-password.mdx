  intent: The full-viewport screen at the end of a password-reset link — one state of the auth flow, presentational, with live rule feedback under the new password.
  whenToUse: "The route an emailed reset link points at: /reset-password?token=…, /account/recover/finish."
  whenNotToUse:
    - case: Asking for the address so a link can be sent
      use: the forgot-password screen — this one is what that link opens
    - case: Changing a password the person still knows
      use: FormLayout in a settings page — this screen never asks for the old password
    - case: A reset form inside a page you already own (a modal, a re-auth step)
      use: the LoginForm block with mode="reset-password" — a block never owns the viewport
    - case: The whole auth journey, with the navigation between its steps
      use: the auth flow, which sequences this screen with sign-in, sign-up, forgot-password and verify
  gotchas:
    - "`token` is the value out of the link, and it rides in a hidden input inside the form rather than in a closure: the reset posts on a page whose JavaScript never arrived. Read it off the URL in the route that mounts this screen."
    - "`requirements` is a list of `{ id, label, met }` and `met` is yours to recompute as the reader types — the screen holds no value and enforces nothing. The server must check every rule again: a rule the browser enforced is a rule an attacker skipped."
    - "The rules are the new-password field's own helper text, so they are in the input's `aria-describedby` and are read on focus. Each row that flips is announced on its own, and the tick is doubled by the word 'met'."
    - "It never asks for the old password. Whoever is on this page followed a link precisely because they do not have it."
    - "An expired or already-used link is `error` plus `disabled`, not a field message: what went wrong is the token, and marking `password` sends the reader off to fix something that was never broken."
    - "`errors.password` is a password the rules reject; `errors.confirmPassword` is two that do not match. Both may be named — the reader holds the token, so there is nothing left to leak."
    - "`notices={[]}` is the screen's empty state: the aside is not rendered at all and the card sits centred and alone."
    - "Full-viewport is a height (`min-h-dvh`). Every width decision is read off the screen's own container, so it is still correct mounted in a pane that is not the window."
    - "The root is a `<div>`, not a `<main>` — most app shells already provide the `main` landmark, and two visible ones in a document is invalid."
    - "The page's `h1` is the card's own title: the screen hands the block `titleLevel={1}` rather than printing a heading of its own above it, so the outline is the card and then the notes' `h2`, with no rank skipped."
  theming:
    - "Nothing is painted here. The card is the LoginForm block and the notes are the AlertList block; the screen's own chrome is `text-foreground` / `text-muted-foreground` on `bg-background`."
    - "Layout comes from the Tailwind preset's contract-backed utilities; the three steps are --container-sm, --container-md and --container-lg."
    - "The default notes are a prop, not a hardcoded FAQ: pass your own, or `[]` to drop the column."

## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onsubmit`) in Svelte, and emits (`submit`, `navigate`) in Vue.

| Prop               | Type                     | Default        | Description                                                           |
| ------------------ | ------------------------ | -------------- | --------------------------------------------------------------------- |
| `token`            | `string`                 | `""`           | The token from the emailed link, posted from a hidden input.          |
| `requirements`     | `PasswordRequirement[]`  | three unticked | Rules under the new password, as `{ id, label, met? }`.               |
| `error`            | `string`                 | —              | Form-level failure: the link expired or was used, or the save failed. |
| `errors`           | `Record<string, string>` | —              | Per-field messages keyed by `password` or `confirmPassword`.          |
| `loading`          | `boolean`                | `false`        | Submit in flight: every control inert, the button busy.               |
| `disabled`         | `boolean`                | `false`        | No password can be set here; pair it with `error`.                    |
| `notices`          | `AlertListItem[]`        | three samples  | Notes beside the card. `[]` hides the aside.                          |
| `noticesError`     | `string`                 | —              | The notes failed to load; this message replaces the list.             |
| `noticesLoading`   | `boolean`                | `false`        | A busy region stands in for the notes.                                |
| `onSubmit`         | `(event) => void`        | —              | Native form submit.                                                   |
| `onNavigate`       | `(to, event) => void`    | —              | A screen link was clicked: `home`, `support`, `privacy` or `terms`.   |
| `onNoticeAction`   | `(id) => void`           | —              | A note's action button, with the note id.                             |
| `onDismissNotice`  | `(id) => void`           | —              | One note was dismissed.                                               |
| `onDismissNotices` | `() => void`             | —              | All notes were dismissed.                                             |
| `onRetryNotices`   | `() => void`             | —              | Retry after `noticesError`.                                           |
| `signInHref`       | `string`                 | `"#"`          | Target of "Sign in" in the card footer.                               |
| `homeHref`         | `string`                 | `"#"`          | Target of the wordmark.                                               |
| `supportHref`      | `string`                 | `"#"`          | Target of "Contact support".                                          |
| `privacyHref`      | `string`                 | `"#"`          | Target of the privacy link.                                           |
| `termsHref`        | `string`                 | `"#"`          | Target of the terms link.                                             |

### States

| State         | Props                          | Renders                                                         |
| ------------- | ------------------------------ | --------------------------------------------------------------- |
| Default       | —                              | New password and confirmation, rules unticked, notes alongside. |
| Rules met     | `requirements` with `met`      | Ticked rows; each is announced as "met" on its own.             |
| Error         | `error` + `disabled`           | A spent or expired link: one alert, the form inert.             |
| Field error   | `errors={{ confirmPassword }}` | That field invalid, with its own message.                       |
| Loading       | `loading`                      | Controls inert, submit `aria-busy`.                             |
| Notes loading | `noticesLoading`               | A busy region in place of the notes.                            |
| Notes error   | `noticesError`                 | An alert in place of the notes.                                 |
| Empty         | `notices={[]}`                 | No aside; the card sits centred and alone.                      |

### Form fields

| Name              | Control      | Posted                                 |
| ----------------- | ------------ | -------------------------------------- |
| `password`        | Password     | Always, `autocomplete="new-password"`. |
| `confirmPassword` | Password     | Always, `autocomplete="new-password"`. |
| `token`           | Hidden input | When `token` is set.                   |

### Sizing

| Container step           | Change                           |
| ------------------------ | -------------------------------- |
| `@sm` (`--container-sm`) | The masthead moves onto one row. |
| `@md` (`--container-md`) | The footer moves onto one row.   |
| `@lg` (`--container-lg`) | The notes move beside the card.  |

### Composition

| Part                         | Role                                                       |
| ---------------------------- | ---------------------------------------------------------- |
| [LoginForm](/en/login-form/) | The card, in `reset-password` mode, with `titleLevel={1}`. |
| [AlertList](/en/alert-list/) | The notes, headed "What this link does".                   |

## Notes

- The rules are the field's helper text, so they are in its `aria-describedby` and read on focus.
- The rule list is a polite live region; colour is never the only sign a rule is met.
- The screen holds no value: recompute `met` in your page. It never blocks a submit.
- Your server must enforce every rule again; the browser list is guidance only.
- An expired or used link is `error` plus `disabled`, never a field error.
- The token rides in a hidden input, so the reset posts as a plain form before hydration.
