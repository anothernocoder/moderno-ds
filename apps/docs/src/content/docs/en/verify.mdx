  intent: The full-viewport screen that checks a one-time code — one state of the auth flow, presentational, with a resend that works without JavaScript.
  whenToUse: "The route an account lands on straight after sign-up: /verify, /confirm-email, /auth/otp."
  whenNotToUse:
    - case: Asking for the address so a code or a link can be sent
      use: the sign-up screen, or forgot-password — this one is what comes after
    - case: A code field inside a page you already own (a re-auth step, a 2FA dialog)
      use: the LoginForm block with mode="verify" — a block never owns the viewport
    - case: A secret of unknown length the person chose themselves
      use: the reset-password screen, or Field with a password input
    - case: The whole auth journey, with the navigation between its steps
      use: the auth flow, which sequences this screen with sign-in, sign-up, forgot-password and reset-password
  gotchas:
    - 'Both buttons submit the same form. Read it with the submitter — `new FormData(form, event.nativeEvent.submitter)` — and branch on `intent`: `"resend"` is the second button, anything else is the check.'
    - "The address rides in a hidden input beside the code, so a resend posted from a page that never hydrated still knows where to send. Pass `sentTo`."
    - "The whole code posts under one name, `code`, from the hidden input Ark keeps in step with the cells. The cells themselves are unnamed."
    - "`resendIn` is a number the screen renders, not a countdown it runs. You own the timer — the screen holds no state, which is what presentational means."
    - "`resent` rewrites the card's header rather than adding a line: the header is already the card's live region, so the confirmation is announced without a second one."
    - "`errors.code` is the wrong or expired code — the cells go `aria-invalid` and the reason prints under them as an `alert`. `error` is the form-level failure: too many attempts, an address already verified."
    - "`codeLength` changes the number of cells *and* the number the description names, so the two can never disagree."
    - "Full-viewport is a height (`min-h-dvh`). Every width decision is read off the screen's own container, so it is still correct mounted in a pane that is not the window."
    - "The root is a `<div>`, not a `<main>` — most app shells already provide the `main` landmark, and two visible ones in a document is invalid."
    - "The page's `h1` is the card's own title: the screen hands the block `titleLevel={1}` rather than printing a heading of its own above it."
  theming:
    - "Nothing is painted here. The card is the LoginForm block; the screen's own chrome is `text-foreground` / `text-muted-foreground` on `bg-background`."
    - "The code cells paint from --input / --background, turn --primary as they fill and --destructive when invalid; their density is PinInput's `size` recipe."
    - "Layout comes from the Tailwind preset's contract-backed utilities; the two steps are --container-sm and --container-md."

## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onsubmit`) in Svelte, and emits (`submit`, `navigate`) in Vue.

| Prop          | Type                     | Default | Description                                                            |
| ------------- | ------------------------ | ------- | ---------------------------------------------------------------------- |
| `sentTo`      | `string`                 | `""`    | The address the code went to, named in the card and posted as `email`. |
| `codeLength`  | `number`                 | `6`     | Number of cells, and the digit count the description names.            |
| `resendIn`    | `number`                 | `0`     | Seconds until a new code can be requested; you run the timer.          |
| `resent`      | `boolean`                | `false` | A new code just went out: the card header says so.                     |
| `error`       | `string`                 | —       | Form-level failure: too many attempts or an already verified address.  |
| `errors`      | `Record<string, string>` | —       | Per-field messages; here only `code`.                                  |
| `loading`     | `boolean`                | `false` | Submit in flight: every control inert, the button busy.                |
| `disabled`    | `boolean`                | `false` | No code can be checked here; pair it with `error`.                     |
| `onSubmit`    | `(event) => void`        | —       | Native form submit, from either button.                                |
| `onNavigate`  | `(to, event) => void`    | —       | A screen link was clicked: `home`, `support`, `privacy` or `terms`.    |
| `signInHref`  | `string`                 | `"#"`   | Target of "Sign in" in the card footer.                                |
| `homeHref`    | `string`                 | `"#"`   | Target of the wordmark.                                                |
| `supportHref` | `string`                 | `"#"`   | Target of "Contact support".                                           |
| `privacyHref` | `string`                 | `"#"`   | Target of the privacy link.                                            |
| `termsHref`   | `string`                 | `"#"`   | Target of the terms link.                                              |

### States

| State         | Props                | Renders                                                           |
| ------------- | -------------------- | ----------------------------------------------------------------- |
| Default       | —                    | The code cells and the resend, ready.                             |
| Field error   | `errors={{ code }}`  | Every cell invalid, with the reason printed below as an `alert`.  |
| Resend locked | `resendIn > 0`       | The resend is disabled and reads "Send a new code in 42s".        |
| Resent        | `resent`             | The header says a new code is on its way and the old one is dead. |
| Error         | `error` + `disabled` | One alert, the form inert.                                        |
| Loading       | `loading`            | Controls inert, submit `aria-busy`.                               |

### Form fields

| Name     | Control            | Posted                                     |
| -------- | ------------------ | ------------------------------------------ |
| `code`   | Hidden input (Ark) | Always; the cells themselves have no name. |
| `email`  | Hidden input       | When `sentTo` is set.                      |
| `intent` | Resend button      | Only by the resend, with `value="resend"`. |

### Sizing

| Container step           | Change                           |
| ------------------------ | -------------------------------- |
| `@sm` (`--container-sm`) | The masthead moves onto one row. |
| `@md` (`--container-md`) | The footer moves onto one row.   |

### Composition

| Part                         | Role                                               |
| ---------------------------- | -------------------------------------------------- |
| [LoginForm](/en/login-form/) | The card, in `verify` mode, with `titleLevel={1}`. |

## Notes

- Both buttons submit the same form; read `new FormData(form, submitter)` to tell a resend from a check.
- The check comes first in the form, so Enter always verifies.
- Every cell has `autocomplete="one-time-code"`, so phones can offer the code from the notification.
- Pasting a code fills every cell; focus moves forward on input and back on Backspace.
- The screen runs no timer: tick `resendIn` down in your page.
- The address rides in a hidden input, so both submits work before hydration.
