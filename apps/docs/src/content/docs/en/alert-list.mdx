**Alert list** is what a single [Alert](/en/alert/) becomes once there is more
than one of them: a stack of statuses, newest first, each dismissible on its
own, under a heading that can clear the lot. It composes `Alert`, `Button` and
`Card` and paints nothing of its own, so a theme re-skins it untouched.

It is a _block_, not a screen: it does not own the viewport and it owns no
notifications either. It renders the `alerts` you hand it and reports what the
reader dismissed — you drop the item from your own state, which is what leaves
an optimistic removal, an undo or a server round-trip yours to decide.

## Installation

<Install item="alert-list" />

Installing a block copies its file into your project and records it in
`.moderno/manifest.json` under its own version, so `moderno update` and
`moderno diff` keep working per item. From that moment the file is yours.

## Sizing

A notification centre is the block most likely to be mounted twice in one app —
once in a 320px drawer, once across an activity page — so all three of its
layout decisions are read off its container:

| Step  | Slot             | What changes                                                                       |
| ----- | ---------------- | ---------------------------------------------------------------------------------- |
| `@sm` | `--container-sm` | The header stops stacking: the heading and "Dismiss all" share a row.              |
| `@md` | `--container-md` | Each row's dismiss control grows its label instead of standing as a glyph.         |
| `@lg` | `--container-lg` | Each timestamp leaves the stack under its title and lines up on the trailing edge. |

None of that reads the window. The same file is correct in a 288px drawer, in a
480px panel, in the page column and on a 50rem stage, in light and dark alike,
without a single media query — which is why the preview above mounts it at four
widths at once and they disagree with each other on one screen. The rules behind
this are in [Blocks and containers](/en/blocks-and-containers/) and ADR-0005.

## States

| State         | What renders                                                                                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default       | The list: one `Alert` per notification, in the status variant that notification speaks in — `info`, `success`, `warning` or `error`.                                |
| Hover         | The controls' own affordances from `components.css`: the dismiss and action buttons take their variant's hover fill.                                                |
| Focus visible | The shared 2px `--ring` outline on every dismiss, every row action and "Dismiss all", in the reading order of the list.                                             |
| Disabled      | `disabled` — the alerts stay readable and every control is inert. A read-only or audit view, not a hidden list.                                                     |
| Loading       | `loading` — a polite busy region stands in for the list, with a spinner that stops under `prefers-reduced-motion`, so nobody acts on rows that are about to change. |
| Empty         | `alerts={[]}` — the list loaded and there is nothing in it, which is a render of its own: "You are all caught up", in a `Card`.                                     |
| Error         | `error` — the list itself could not be loaded, so one `Alert` says so and offers a retry. An empty list and a failed one are different facts.                       |

The four status variants all appear in the sample feed above, in the order a
reader needs them: what is broken, what is about to break, what changed, what
went right.

## Props

| Prop           | Type              | Default           | What it does                                                                                      |
| -------------- | ----------------- | ----------------- | ------------------------------------------------------------------------------------------------- |
| `alerts`       | `AlertListItem[]` | a sample feed     | The notifications to render, newest first. `[]` renders the empty state.                          |
| `heading`      | `string`          | `"Notifications"` | The heading over the stack — what this collection _is_.                                           |
| `description`  | `string`          | a sentence        | The line under the heading; pass `""` for a heading on its own.                                   |
| `error`        | `string`          | —                 | The list could not be loaded; this message replaces it.                                           |
| `loading`      | `boolean`         | `false`           | The list is being loaded or refreshed: a busy region stands in for it.                            |
| `disabled`     | `boolean`         | `false`           | Read-only: the alerts stay on screen and every control is inert.                                  |
| `onDismiss`    | `(id) => void`    | —                 | One row's dismiss control. React/Solid take `onDismiss`, Svelte `ondismiss`, Vue emits `dismiss`. |
| `onDismissAll` | `() => void`      | —                 | Clear the whole list. Svelte `ondismissall`, Vue emits `dismissAll`.                              |
| `onAction`     | `(id) => void`    | —                 | A row's own action (`actionLabel`), with that row's id. Svelte `onaction`, Vue emits `action`.    |
| `onRetry`      | `() => void`      | —                 | Retry after `error`. Svelte `onretry`, Vue emits `retry`.                                         |

An `AlertListItem` is `{ id, variant, title, description?, meta?, actionLabel? }`
— `variant` is one of Alert's four statuses, `meta` is the timestamp already
phrased for a reader, and a row with no `actionLabel` is news rather than a task.
