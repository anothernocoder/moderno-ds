## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onstepchange`) in Svelte, and emits (`stepChange`, `invite`) in Vue.

| Prop             | Type               | Default                            | Description                                                       |
| ---------------- | ------------------ | ---------------------------------- | ----------------------------------------------------------------- |
| `initialStep`    | `ReferralStep`     | `"referral-invite"`                | The screen the flow opens on; in an app, whatever the route says. |
| `initialFriends` | `ReferralFriend[]` | `[]`                               | Friends invited before this visit: `{ id, name, email, status }`. |
| `link`           | `string`           | `"https://example.com/r/ana-ruiz"` | The member's own referral link, on the share screen.              |
| `reward`         | `string`           | `"a free month"`                   | What each side gets when a friend joins.                          |
| `hrefFor`        | `(step) => string` | `` `#${step}` ``                   | The URL of each step; drives both the links and the interception. |
| `onStepChange`   | `(step) => void`   | —                                  | The flow moved; mirror it in the URL.                             |
| `onInvite`       | `(emails) => void` | —                                  | Friends were invited, from either screen. Only new addresses.     |
| `homeHref`       | `string`           | `"#"`                              | Target of the wordmark on every screen.                           |
| `rulesHref`      | `string`           | `"#"`                              | Target of "How referrals work" on the invite screen.              |
| `privacyHref`    | `string`           | `"#"`                              | Target of the privacy links on every screen.                      |
| `termsHref`      | `string`           | `"#"`                              | Target of the terms links on every screen.                        |

### Steps

`ReferralStep` is one of the three screens, in the order the flow moves through them.

| Step                                      | Reached by                                   | Leaves for                                       |
| ----------------------------------------- | -------------------------------------------- | ------------------------------------------------ |
| [`referral-invite`](/en/referral-invite/) | The first step                               | `referral-share`, on "Send invites" or "Not now" |
| [`referral-share`](/en/referral-share/)   | A sent invite form, or "Invite more friends" | `referral-reward`, on "Skip for now"             |
| [`referral-reward`](/en/referral-reward/) | "Skip for now"                               | `referral-share`, on "Invite more friends"       |

### State

What the assembly holds so the screens don't have to.

| State     | Holds                                                                     |
| --------- | ------------------------------------------------------------------------- |
| `step`    | The screen currently on the route.                                        |
| `friends` | Everyone invited so far. The share screen lists it; the reward counts it. |
| `errors`  | Whatever the last invite form rejected.                                   |

## Notes

- The assembly is example code, the one file you are expected to rewrite. The screens stay as shipped.
- Navigation intercepts real `href`s: plain left clicks only; modified and middle clicks go to the browser.
- The invite form is a plain form submission, read off its `emails` field and split on commas and new lines.
- `errors` resets on every move.
- The reward numbers are counted from `friends` on every render, so they never disagree with the share screen's list.
