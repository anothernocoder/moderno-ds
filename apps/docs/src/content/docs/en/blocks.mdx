A **block** is a page _section_ composed of primitives — a hero, a pricing
table, a login form. You copy it into your project with the CLI and own it from
that moment on; it is not an npm dependency.

A block never owns the viewport and carries no navigation state. It responds to
its **container**, not the viewport, so the same block looks right in a sidebar,
a modal or a full page without knowing which.

```sh
npx @moderno-ui/cli add login-form-react
```

Installing a block also installs the registry items it composes — ejected
primitives, if it uses any — and records each one under its own version in
`.moderno/manifest.json`, so `moderno update` and `moderno diff` stay per item.

A block composes only primitives, never a screen or a flow — the registry
enforces that direction. The catalog is being filled as the predecessor's
inventory is absorbed; each published block gets its own page in this section.

## Section layout is not painted yet

Those previews look plain, and that is the honest state rather than a rendering
fault. A block's primitives are fully painted by `components.css`, but the
block's own wrapper carries a bare `moderno-block-*` class with **no rules on
`main`** — no grid, no spacing scale, no card surface. Section layout arrives
with the container-query styling pipeline described in ADR-0005.

Showing the gap is the point: these previews are captured by the visual suite,
so when the pipeline lands, the baselines move and the change has to be reviewed
rather than noticed later.
