  intent: Enter a short code the user received out of band — an SMS OTP, an emailed verification code, a 2FA token.
  whenToUse: A fixed-length code where each character deserves its own cell and the whole code is submitted at once.
  whenNotToUse:
    - case: Free-form secret of unknown length (a password)
      use: Field with a password input
    - case: A number the user reasons about (quantity, amount)
      use: Number Input
  gotchas:
    - "Each cell is authored by the consumer: render one PinInput.Input per index inside PinInput.Control."
    - "Pass count on the Root so the server-rendered aria labels match the client's; without it SSR labels say 'of 0'."
    - "Add PinInput.HiddenInput when the code must be submitted with a form — that's the named field."
    - "type defaults to numeric (cells render as type=tel); use alphanumeric for a mixed code."
    - "invalid/complete/filled are Ark data-attributes, not props of the recipe; style them, don't recreate them."
  theming:
    - Cells paint from --input / --background and turn --primary as they fill, --destructive when invalid.
    - Cell width and height come from --spacing-*; size is the only visual knob.

Only `PinInput.Root` is wrapped, to inject the `size` recipe's `data-size`;
every other part is Ark's verbatim. Ark advances focus as characters land,
retreats on backspace, distributes a pasted code across the cells, swaps them to
`type="password"` when `mask` is set, and mirrors `invalid` onto `aria-invalid`
plus a `data-invalid` on every part — so `components.css` styles the filled,
complete and invalid states without the binding tracking any of them.

<PinInput.Root count={cells.length} otp onValueComplete={submit}>

    {cells.map((index) => (

  <PinInput.HiddenInput />
</PinInput.Root>`}
