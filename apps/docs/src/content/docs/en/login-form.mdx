agent:
  intent: The credential card of an authentication screen, in its sign-in, sign-up, forgot-password, reset-password or verify mode.
  whenToUse: 'A page or panel where someone enters credentials: a sign-in screen, a registration screen (mode="sign-up"), a password-recovery screen (mode="forgot-password"), the page behind an emailed reset link (mode="reset-password"), the one-time code that follows a sign-up (mode="verify"), a re-authentication step, a modal that unlocks a privileged action.'
  whenNotToUse:
    - case: A one-time code with no card around it — inside a dialog you already styled, or a step of your own
      use: PinInput directly; this block is the card, and mode="verify" is what puts a code inside it
    - case: A full-viewport page with its own heading, highlights and footer
      use: the sign-in, sign-up, forgot-password, reset-password or verify screen, each of which composes this block in one mode
    - case: Changing a password the person still knows
      use: FormLayout — reset-password never asks for the old one, because whoever is on that page does not have it
    - case: A long form of grouped fields with one actions row
      use: FormLayout — settings, profile, billing; this card is credentials only
    - case: A generic form of your own fields
      use: Field and Button directly
  gotchas:
    - "Presentational: it holds no credentials and issues no request. Pass `error` / `loading` / `disabled` and handle the native submit event yourself."
    - "`mode` decides which card this is: `sign-in` (the default), `sign-up`, `forgot-password`, `reset-password` or `verify`. It changes the fields, the copy, the submit, the secondary row and the footer link; everything else — width, spacing, states — is shared."
    - '`sent` is read in `forgot-password` only: the same card confirms in place instead of asking, names `sentTo` in the sentence and carries it in a hidden input, so "Send it again" is a plain form submission that works unhydrated. The confirmation says "if that address has an account" and never whether it does.'
    - "`error` is a form-level message. Signing in it also invalidates both credential fields and names neither, so the form never confirms that an email address exists; signing up there is nothing to leak yet, so `errors` (keyed by the field's `name`: `fullName`, `email`, `password`) names the field that was rejected."
    - '`errors` is read in every mode but `sign-in`, and the terms links (`termsHref` / `privacyHref`) render in `sign-up` only — as does the required consent checkbox, which is `name="terms"` in the submitted form.'
    - "`reset-password` submits three named controls: `password`, `confirmPassword` and — when you pass `token` — a hidden `token` carrying the value out of the emailed link, so the reset posts unhydrated. It never asks for the old password: whoever is on that page does not have it."
    - '`verify` renders PinInput: `codeLength` cells (6 by default), all `autocomplete="one-time-code"`, submitting the whole code under one name — `code` — from the hidden input Ark keeps in step with them. `sentTo` is named in the description and rides in a hidden `email`, so a resend posts unhydrated.'
    - 'The `verify` resend is a second submit button, `name="intent" value="resend"`, not a callback: read `new FormData(form, submitter)` and branch on `intent`. `resendIn` (seconds) locks it and counts down — you own that timer — and `resent` rewrites the header, which is already the card''s live region.'
    - "`errors.code` marks the cells invalid and prints the reason under them as an `alert`; a pin input is n controls and one value, so there is no single field to describe."
    - "`requirements` is the rules under the new password (`{ id, label, met }`), rendered as that field's helper text so a screen reader reads them on focus. `met` is yours to recompute as the value changes; the block holds no value and enforces nothing, and the server must check every rule again."
    - "`loading` implies inert: every control is disabled and the submit carries aria-busy, so a second submit cannot be fired mid-request."
    - "The block responds to its container, never the viewport. Mount it in something narrower than --container-sm and the secondary row stacks on its own."
    - "`titleLevel` is the rank the card's title carries in the page's heading outline. It defaults to `3` — a card is a section of a page, not its heading — and a screen that mounts this card as the whole route passes `1`, so the document has a top-level heading and nothing after it skips a rank."
    - "In `forgot-password` the card's header is a live region, so the confirmation that rewrites it in place is announced and not only seen."
    - "It is a block, so you own the copy: the labels, the links and the hrefs are yours to edit after `moderno add`."
  theming:
    - "The surface is Card (--card, --border, --radius); the controls are Field and Checkbox; the submit is Button's primary variant. Nothing is painted here."
    - "The error alert reads --destructive through Alert's error variant, so a destructive action and a failed sign-in speak with one voice."
    - "Layout comes from the Tailwind preset's contract-backed utilities; the card's width cap is --container-sm."

## API Reference

### Props

| Prop           | Type                                                                          | Default           | Description                                                             |
| -------------- | ----------------------------------------------------------------------------- | ----------------- | ----------------------------------------------------------------------- |
| `mode`         | `"sign-in" \| "sign-up" \| "forgot-password" \| "reset-password" \| "verify"` | `"sign-in"`       | Which card renders. See [Modes](#modes).                                |
| `titleLevel`   | `1 \| 2 \| 3`                                                                 | `3`               | Heading rank of the card title; a full-page screen passes `1`.          |
| `sent`         | `boolean`                                                                     | `false`           | `forgot-password`: the card confirms the link was sent.                 |
| `sentTo`       | `string`                                                                      | `""`              | `forgot-password`, `verify`: the address, named and sent as `email`.    |
| `codeLength`   | `number`                                                                      | `6`               | `verify`: the number of code cells.                                     |
| `resendIn`     | `number`                                                                      | `0`               | `verify`: seconds until the resend unlocks. You own the timer.          |
| `resent`       | `boolean`                                                                     | `false`           | `verify`: the header says a new code is on its way.                     |
| `token`        | `string`                                                                      | `""`              | `reset-password`: the emailed token, submitted as a hidden `token`.     |
| `requirements` | `PasswordRequirement[]`                                                       | three unmet rules | `reset-password`: rules under the new password; `[]` shows helper text. |
| `error`        | `string`                                                                      | —                 | Form-level alert. In `sign-in` it also marks both fields invalid.       |
| `errors`       | `Record<string, string>`                                                      | —                 | Per-field messages keyed by field `name`. Not read in `sign-in`.        |
| `loading`      | `boolean`                                                                     | `false`           | Disables every control and marks the submit `aria-busy`.                |
| `disabled`     | `boolean`                                                                     | `false`           | The form is unavailable, such as an SSO-only workspace.                 |
| `onSubmit`     | `(event) => void`                                                             | —                 | Native submit event. Svelte: `onsubmit`. Vue: `@submit`.                |
| `forgotHref`   | `string`                                                                      | `"#"`             | `sign-in`: the "Forgot your password?" link.                            |
| `signUpHref`   | `string`                                                                      | `"#"`             | `sign-in`: the "Create an account" link.                                |
| `signInHref`   | `string`                                                                      | `"#"`             | Every other mode: the "Sign in" link.                                   |
| `termsHref`    | `string`                                                                      | `"#"`             | `sign-up`: the terms link under the consent box.                        |
| `privacyHref`  | `string`                                                                      | `"#"`             | `sign-up`: the privacy link under the consent box.                      |

### PasswordRequirement

| Field   | Type      | Description                                             |
| ------- | --------- | ------------------------------------------------------- |
| `id`    | `string`  | Stable key for the row.                                 |
| `label` | `string`  | The rule in words, e.g. "At least 12 characters".       |
| `met`   | `boolean` | Whether the current value satisfies it. You compute it. |

### Modes

| Mode                | Fields                                  | Submitted names                          | Footer link                        |
| ------------------- | --------------------------------------- | ---------------------------------------- | ---------------------------------- |
| `sign-in` (default) | Email, password, remember me            | `email`, `password`, `remember`          | "New here? Create an account"      |
| `sign-up`           | Full name, email, password, consent box | `fullName`, `email`, `password`, `terms` | "Already have an account? Sign in" |
| `forgot-password`   | Email; with `sent`, a confirmation      | `email`                                  | "Remembered it? Sign in"           |
| `reset-password`    | New password, confirmation, rules       | `password`, `confirmPassword`, `token`   | "Changed your mind? Sign in"       |
| `verify`            | One cell per digit, a resend button     | `code`, `email`, `intent`                | "Wrong account? Sign in"           |

Each mode also has a live preview on its screen page: [sign in](/en/sign-in/), [sign up](/en/sign-up/), [forgot password](/en/forgot-password/), [reset password](/en/reset-password/) and [verify](/en/verify/).

### States

| State         | Prop                     | What renders                                                                   |
| ------------- | ------------------------ | ------------------------------------------------------------------------------ |
| Default       | —                        | The empty form with placeholders.                                              |
| Disabled      | `disabled`               | Every control disabled.                                                        |
| Loading       | `loading`                | Every control disabled; the submit shows a spinner and `aria-busy`.            |
| Error         | `error`                  | One form-level alert; in `sign-in` both credential fields go invalid.          |
| Field errors  | `errors`                 | The named field goes invalid and prints its message. Not in `sign-in`.         |
| Sent          | `sent`                   | `forgot-password`: "Check your inbox", and the submit becomes "Send it again". |
| Rules         | `requirements`           | `reset-password`: each rule reads "met" or "not met yet".                      |
| Code rejected | `errors={{ code: "…" }}` | `verify`: every cell goes invalid and the message prints as an `alert`.        |
| Resend locked | `resendIn`               | `verify`: the resend is disabled and shows the seconds left.                   |
| Resent        | `resent`                 | `verify`: the header says a new code was sent and the old one stopped working. |

### Sizing

The card caps at `--container-sm` (24rem) and responds to its container, not the viewport. The remember-me row stacks below `@sm` and the title steps up at `@md`.

## Notes

- Presentational: it holds no credentials and sends no request. Handle the native submit yourself.
- A `sign-in` error never says which field was wrong, so it can't confirm that an account exists.
- The `forgot-password` confirmation says "if that address has an account" whether or not it does.
- The resend, the emailed token and the address ride in the form, so every submit works without JavaScript.
- In `forgot-password` and `verify` the card header is a live region, so `sent` and `resent` are announced.
- The rules are the password field's helper text and a polite live region; the server must still enforce them.
