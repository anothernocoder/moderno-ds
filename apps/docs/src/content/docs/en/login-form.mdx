**Login form** is the credential card, and it has two modes.
`mode="sign-in"` — the default — is the returning person: an email field, a
password field, remember-me, and the two links every sign-in screen needs.
`mode="sign-up"` is the new one: full name, email, a new password, and the
consent that has to be given before an account can exist. It composes `Card`,
`Field`, `Checkbox`, `Button` and `Alert` and paints nothing of its own, so a
theme re-skins it untouched.

One block rather than two, because they are one thing: the same card, the same
width cap, the same rhythm — so a person moving between
[sign in](/en/sign-in/) and [sign up](/en/sign-up/) does not feel the page
change under them.

It is a _block_, not a screen: it does not own the viewport, holds no navigation
state and issues no request. The `sign-in` and `sign-up` screens compose it and
keep the state; this file is a section you can also drop into a modal or a
settings panel.

## Installation

<Install item="login-form" />

Installing a block copies its file into your project and records it in
`.moderno/manifest.json` under its own version, so `moderno update` and
`moderno diff` keep working per item. From that moment the file is yours.

## Sizing

The block responds to **its container**, never the window. The card caps itself
at `--container-sm` (24rem) — a credential field wider than that is harder to
read, not easier — and the secondary row (remember-me plus the recovery link)
stacks below the `@sm` step and sits on one line at or above it. The heading
steps up at `@md`, where the section has room to breathe.

That is why the same file is correct in a 320px sidebar, inside a card and
centred on a 1280px page, in light and dark alike, without a single media query.
The rules behind this are in [Blocks and containers](/en/blocks-and-containers/)
and ADR-0005.

## Modes

`mode` changes what the card asks for and nothing else — the width cap, the
spacing, the container steps and every state below are shared.

| Mode                | Fields                                      | Secondary row                         | Footer link                        |
| ------------------- | ------------------------------------------- | ------------------------------------- | ---------------------------------- |
| `sign-in` (default) | Email, password (`current-password`)        | Remember me + "Forgot your password?" | "New here? Create an account"      |
| `sign-up`           | Full name, email, password (`new-password`) | Required consent box + legal links    | "Already have an account? Sign in" |

The preview above is the `sign-in` mode in its container widths and states; the
`sign-up` mode is previewed on the [sign-up screen](/en/sign-up/) page, mounted
in the screen that composes it.

## States

| State           | What renders                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Default / empty | The pristine form — placeholders, no values. A sign-in form has no collection to be empty of, so these are the same render. |
| Hover           | The controls' own affordances from `components.css`; both links raise to `--foreground` and underline.                      |
| Focus visible   | The shared 2px `--ring` outline on every control, and on the two links.                                                     |
| Disabled        | `disabled` — sign-in is unavailable (an SSO-only workspace, a locked account).                                              |
| Loading         | `loading` — every control inert, the submit `aria-busy` with a spinner that stops under `prefers-reduced-motion`.           |
| Error           | `error="…"` — one form-level `Alert`; in `sign-in` both credential fields also go invalid.                                  |
| Field errors    | `errors={{ email: "…" }}` — `sign-up` only: that field is invalid and prints its own message under the input.               |

Signing in, the error is deliberately form-level. Telling a visitor that _the
password_ was wrong also tells them the email exists, which is the first half of
a credential stuffing run; the block never does that, and neither should the code
you wire behind it. Signing up, that argument is gone — the address is being
offered, not guessed — and a form that will not say which field it rejected is
merely rude, so `errors` names them.

## Props

| Prop          | Type                     | Default     | What it does                                                                                    |
| ------------- | ------------------------ | ----------- | ----------------------------------------------------------------------------------------------- |
| `mode`        | `"sign-in" \| "sign-up"` | `"sign-in"` | Which card this is: the returning person, or the new one.                                       |
| `error`       | `string`                 | —           | Form-level failure message; renders the alert, and in `sign-in` invalidates both fields.        |
| `errors`      | `Record<string, string>` | —           | `sign-up` only — per-field messages keyed by the field's `name`; each marks that field invalid. |
| `loading`     | `boolean`                | `false`     | The submit is in flight: controls inert, button busy.                                           |
| `disabled`    | `boolean`                | `false`     | The form is unavailable (SSO-only workspace, locked account, closed beta).                      |
| `onSubmit`    | submit handler           | —           | The native submit event. React/Solid take `onSubmit`, Svelte `onsubmit`, Vue emits `submit`.    |
| `forgotHref`  | `string`                 | `"#"`       | `sign-in` — where "Forgot your password?" points.                                               |
| `signUpHref`  | `string`                 | `"#"`       | `sign-in` — where "Create an account" points.                                                   |
| `signInHref`  | `string`                 | `"#"`       | `sign-up` — where "Sign in" points.                                                             |
| `termsHref`   | `string`                 | `"#"`       | `sign-up` — where the terms link under the consent box points.                                  |
| `privacyHref` | `string`                 | `"#"`       | `sign-up` — where the privacy link under the consent box points.                                |
