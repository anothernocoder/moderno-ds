## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onsubmit`) in Svelte, and emits (`submit`, `cancel`, `navigate`) in Vue.

| Prop          | Type                     | Default | Description                                                       |
| ------------- | ------------------------ | ------- | ----------------------------------------------------------------- |
| `sent`        | `string[]`               | —       | Addresses the last send reached. Shows the success alert.         |
| `error`       | `string`                 | —       | Sending failed: shows the form alert.                             |
| `errors`      | `Record<string, string>` | —       | Field errors by name: `emails`, `message`.                        |
| `loading`     | `boolean`                | `false` | Send in flight: every control inert, the send button busy.        |
| `disabled`    | `boolean`                | `false` | No invites can be sent right now.                                 |
| `onSubmit`    | `(event) => void`        | —       | Native form submit.                                               |
| `onCancel`    | `() => void`             | —       | The form's "Not now" button was pressed.                          |
| `onNavigate`  | `(to, event) => void`    | —       | A screen link was clicked: `home`, `rules`, `privacy` or `terms`. |
| `homeHref`    | `string`                 | `"#"`   | Target of the wordmark.                                           |
| `rulesHref`   | `string`                 | `"#"`   | Target of "How referrals work".                                   |
| `privacyHref` | `string`                 | `"#"`   | Target of the privacy link.                                       |
| `termsHref`   | `string`                 | `"#"`   | Target of the terms link.                                         |

### States

| State      | Props             | Renders                                           |
| ---------- | ----------------- | ------------------------------------------------- |
| Empty      | —                 | The steps and the empty form. Nothing sent yet.   |
| Sent       | `sent`            | A success alert naming the addresses.             |
| Send error | `error`, `errors` | The form alert and the invalid fields.            |
| Sending    | `loading`         | Every control inert, the send button `aria-busy`. |
| Disabled   | `disabled`        | The screen is shown but can't be used.            |

### Form fields

| Name      | Control  | Posted                                      |
| --------- | -------- | ------------------------------------------- |
| `emails`  | Textarea | Always. Addresses split by commas or lines. |
| `message` | Textarea | Always. Empty when the note is left blank.  |

### Sizing

| Container step           | Change                                                            |
| ------------------------ | ----------------------------------------------------------------- |
| `@sm` (`--container-sm`) | The masthead moves onto one row.                                  |
| `@md` (`--container-md`) | The title grows, the steps sit side by side, the footer lines up. |

### Composition

| Part                           | Role                                                 |
| ------------------------------ | ---------------------------------------------------- |
| [FormLayout](/en/form-layout/) | The form: its title, the fields and the send button. |
| [Alert](/en/alert/)            | The success message after a send.                    |
| [Field](/en/field/)            | The addresses and the note, inside the form.         |

## Notes

- Presentational: no request, no parsing, no router. The page that mounts it owns them.
- Split `emails` on commas and new lines, trim each part and drop the empty ones before you check them.
- Pair `disabled` with an `error` that says why, like a weekly limit, so the reader knows when to come back.
- `onNavigate` passes the click event: skip `metaKey`/`ctrlKey` clicks, then `preventDefault()` to route.
- The screen imports the FormLayout block from `@/components/blocks/…`; edit that line if your alias differs.
