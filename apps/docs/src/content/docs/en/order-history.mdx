## Usage

Use Order History on an account page, so a shopper can see what they bought and where each order is. Each order shows its status as a badge.

<ForFramework fw="react">

```tsx
import { OrderHistory } from "@/components/blocks/order-history";
```

```tsx
<OrderHistory orders={orders} onView={(id) => openOrder(id)} />
```

</ForFramework>
<ForFramework fw="vue">

```vue
<script setup lang="ts">
import OrderHistory from "@/components/blocks/OrderHistory.vue";
</script>
```

```vue
<OrderHistory :orders="orders" @view="openOrder" />
```

</ForFramework>
<ForFramework fw="svelte">

```svelte
<script lang="ts">
  import OrderHistory from "@/components/blocks/OrderHistory.svelte";
</script>
```

```svelte
<OrderHistory {orders} onview={(id) => openOrder(id)} />
```

</ForFramework>
<ForFramework fw="solid">

```tsx
import { OrderHistory } from "@/components/blocks/order-history";
```

```tsx
<OrderHistory orders={orders()} onView={(id) => openOrder(id)} />
```

</ForFramework>

Each order looks like `{ id: "wu88191111", number: "WU88191111", date: "6 Jan 2026", total: "€134", status: "Shipped", statusVariant: "info", items: [...] }`. The block does no maths and no date formatting: pass every value as people read it.

## API Reference

### Props

| Prop          | Type                   | Default                                     | Description                                                                 |
| ------------- | ---------------------- | ------------------------------------------- | --------------------------------------------------------------------------- |
| `heading`     | `string`               | `"Order history"`                           | The section's heading. It is set in the serif face.                         |
| `description` | `string`               | `"Check the status of your recent orders."` | The line under the heading. An empty string hides it.                       |
| `orders`      | `OrderHistoryOrder[]`  | three sample orders                         | The orders, in the order you pass them. `[]` shows the empty message.       |
| `error`       | `string`               | —                                           | Loading the orders failed; an error Alert with a retry replaces the orders. |
| `loading`     | `boolean`              | `false`                                     | Placeholder orders in a busy region replace the orders.                     |
| `disabled`    | `boolean`              | `false`                                     | The orders stay; every "View order" button and the retry are off.           |
| `onView`      | `(id: string) => void` | —                                           | "View order" on an order, with its `id`. Svelte: `onview`. Vue: `@view`.    |
| `onRetry`     | `() => void`           | —                                           | "Try again" after `error`. Svelte: `onretry`. Vue: `@retry`.                |

### OrderHistoryOrder

| Field           | Type                 | Description                                                        |
| --------------- | -------------------- | ------------------------------------------------------------------ |
| `id`            | `string`             | A stable key, passed to `onView`.                                  |
| `number`        | `string`             | The order number people see. It reads "Order WU88191111".          |
| `date`          | `string`             | When the order was placed, like `"6 Jan 2026"`.                    |
| `total`         | `string`             | What the order cost, like `"€134"`.                                |
| `status`        | `string`             | The badge's text, like `"Shipped"`.                                |
| `statusVariant` | `BadgeVariant`       | Optional. The badge's colour, like `"success"`. Default `neutral`. |
| `items`         | `OrderHistoryItem[]` | The lines in the order.                                            |

### OrderHistoryItem

| Field      | Type                    | Description                                                   |
| ---------- | ----------------------- | ------------------------------------------------------------- |
| `id`       | `string`                | A stable key for the line.                                    |
| `name`     | `string`                | The product's name.                                           |
| `price`    | `string`                | The line's price for its whole quantity, like `"€56"`.        |
| `quantity` | `number`                | How many were ordered. It reads "Qty 2".                      |
| `image`    | `OrderHistoryItemImage` | Optional. The photo: `{ src, alt }`. Without it, a muted box. |

### States

| State    | Prop          | What renders                                                |
| -------- | ------------- | ----------------------------------------------------------- |
| Default  | —             | The heading, the description and one card per order.        |
| Empty    | `orders={[]}` | The heading and "You have not placed any orders yet."       |
| Loading  | `loading`     | The heading and two placeholder orders.                     |
| Error    | `error`       | The heading and an error Alert with "Try again".            |
| Disabled | `disabled`    | The same orders, with every "View order" and the retry off. |

### Sizing

| Container step           | What changes                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------- |
| below `@sm`              | The date and total stack, one per row. The button spans the card. Small images.         |
| `@sm` (`--container-sm`) | The date and total sit side by side, the button moves beside them, and the images grow. |
| `@md` (`--container-md`) | Each line's quantity moves into its own column, before the price. The heading steps up. |
| `@lg` (`--container-lg`) | More room above and below the block, and between the orders.                            |

## Notes

- Keep status words short: one or two words fit on one line with the order number.
- Show the most recent orders and page through the rest, rather than passing every order at once.
