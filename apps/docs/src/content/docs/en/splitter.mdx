## Usage

Splitter puts panels side by side and lets the user drag the handle between them to resize them. Use it when the user should decide how much room each part gets, like a file tree beside an editor.

<ForFramework fw="react">

```tsx
import { Splitter } from "@moderno-ui/react";
```

```tsx
<Splitter.Root
  panels={[
    { id: "files", minSize: 20 },
    { id: "editor", minSize: 30 },
  ]}
  defaultSize={[30, 70]}
>
  <Splitter.Panel id="files">Files</Splitter.Panel>
  <Splitter.ResizeTrigger id="files:editor" aria-label="Resize files and editor">
    <Splitter.ResizeTriggerIndicator />
  </Splitter.ResizeTrigger>
  <Splitter.Panel id="editor">Editor</Splitter.Panel>
</Splitter.Root>
```

</ForFramework>

Each panel has an id, listed in `panels` in order. Sizes are percentages. The handle's id joins the ids of the two panels it sits between. The splitter fills its container, so give the container a height.

With the handle focused, the arrow keys move it, Home and End push it as far as it goes, and Enter folds away a collapsible panel.

## API Reference

### Splitter.Root

`variant` is the Moderno addition. The other props come from Ark's Splitter.

<PropsTable component="Splitter" />

| Prop               | Type                                                   | Default        | Description                                                  |
| ------------------ | ------------------------------------------------------ | -------------- | ------------------------------------------------------------ |
| `panels`           | `PanelData[]`                                          | —              | Required. Every panel, in order: its `id` and limits.        |
| `defaultSize`      | `number[]`                                             | —              | Sizes at first when uncontrolled, in percent, one per panel. |
| `size`             | `number[]`                                             | —              | Controlled sizes, in percent. Not a density.                 |
| `onResize`         | `(details: { size: number[] }) => void`                | —              | Called while the sizes change.                               |
| `onResizeEnd`      | `(details: { size: number[] }) => void`                | —              | Called once, when the user lets go.                          |
| `onCollapse`       | `(details: { panelId: string; size: number }) => void` | —              | Called when a panel folds away.                              |
| `onExpand`         | `(details: { panelId: string; size: number }) => void` | —              | Called when a folded panel opens again.                      |
| `orientation`      | `"horizontal" \| "vertical"`                           | `"horizontal"` | Sets the panels side by side or stacks them.                 |
| `keyboardResizeBy` | `number`                                               | `1`            | How far, in percent, one arrow key moves the handle.         |

In Vue, bind controlled sizes with `v-model:size`, and listen with `@resize`.

### PanelData

One entry of `panels`.

| Field           | Type               | Default | Description                                    |
| --------------- | ------------------ | ------- | ---------------------------------------------- |
| `id`            | `string`           | —       | Required. The id its `Splitter.Panel` carries. |
| `minSize`       | `number \| string` | —       | The smallest it gets, in percent or pixels.    |
| `maxSize`       | `number \| string` | —       | The largest it gets, in percent or pixels.     |
| `collapsible`   | `boolean`          | `false` | Lets it fold away below its `minSize`.         |
| `collapsedSize` | `number \| string` | `0`     | Its size when folded away.                     |

### Splitter.ResizeTrigger

| Prop       | Type      | Default | Description                                           |
| ---------- | --------- | ------- | ----------------------------------------------------- |
| `id`       | `string`  | —       | Required. The two panel ids around it: `"a:b"`.       |
| `disabled` | `boolean` | `false` | Locks this handle: no dragging, out of the tab order. |

### Parts

| Part                              | Element    | Description                                                     |
| --------------------------------- | ---------- | --------------------------------------------------------------- |
| `Splitter.Root`                   | `<div>`    | Carries `data-variant`. Lays the panels out in a row or column. |
| `Splitter.Panel`                  | `<div>`    | One panel. Ark sets its size inline.                            |
| `Splitter.ResizeTrigger`          | `<button>` | The handle, with `role="separator"` and `aria-valuenow`.        |
| `Splitter.ResizeTriggerIndicator` | `<div>`    | Optional, inside a handle. The grip drawn on the rule.          |

### Data attributes

| Attribute          | Values                                                         |
| ------------------ | -------------------------------------------------------------- |
| `data-orientation` | `"horizontal"` or `"vertical"`, on every part                  |
| `data-dragging`    | While a handle is dragged, on the root, panels and that handle |
| `data-focus`       | While a handle has focus, on it and its grip                   |
| `data-disabled`    | On a disabled handle and its grip                              |
| `data-id`          | On each panel and handle: its id                               |
| `data-variant`     | On the root: `"line"` or `"enclosed"`                          |

## Notes

- `Splitter.Root` is wrapped to add `variant`; every other part is Ark's unchanged.
- There is no `size` variant: on the Root, `size` is Ark's controlled panel sizes.
- A panel has the UI type but no padding, since padding would skew its size. Put your own padded layout inside it.
- In Solid and Svelte, the Root gives Ark a stand-in document on the server, so a server render does not throw.
