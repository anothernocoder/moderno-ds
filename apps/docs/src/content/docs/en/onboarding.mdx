## Usage

<ForFramework fw="react">


## API Reference

### Props

Callbacks are `on…` props in React and Solid, lowercase (`onstepchange`) in Svelte, and emits (`stepChange`, `complete`) in Vue.

| Prop           | Type               | Default          | Description                                                       |
| -------------- | ------------------ | ---------------- | ----------------------------------------------------------------- |
| `initialStep`  | `OnboardingStep`   | `"welcome"`      | The screen the flow opens on; in an app, whatever the route says. |
| `initialName`  | `string`           | `""`             | The reader's full name, if sign-up already asked for it.          |
| `hrefFor`      | `(step) => string` | `` `#${step}` `` | The URL of each step; drives the skip links.                      |
| `finishHref`   | `string`           | `"#"`            | Where the app begins: the target of Skip on the last step.        |
| `onStepChange` | `(step) => void`   | —                | The flow moved; mirror it in the URL.                             |
| `onComplete`   | `(result) => void` | —                | The reader is through, finished or skipped.                       |
| `homeHref`     | `string`           | `"#"`            | Target of the wordmark on every screen.                           |
| `supportHref`  | `string`           | `"#"`            | Target of "Contact support" on welcome.                           |
| `salesHref`    | `string`           | `"#"`            | Target of "Talk to sales" on plan-select.                         |
| `privacyHref`  | `string`           | `"#"`            | Target of the privacy links on every screen.                      |
| `termsHref`    | `string`           | `"#"`            | Target of the terms links on every screen.                        |

`result` is `{ name: string; plan?: string; invites: string[] }`: the saved name, the chosen plan's `id` and every address invited.

### Steps

`OnboardingStep` is one of the four screens, in the order the flow moves through them.

| Step                                  | Leaves for                                                          |
| ------------------------------------- | ------------------------------------------------------------------- |
| [`welcome`](/en/welcome/)             | `profile-setup` on Continue; `onComplete` on Skip for now           |
| [`profile-setup`](/en/profile-setup/) | `plan-select` on a saved profile or Skip; `welcome` on Cancel       |
| [`plan-select`](/en/plan-select/)     | `invite-team` once a plan is chosen                                 |
| [`invite-team`](/en/invite-team/)     | `onComplete` on Continue or Skip; sending invites stays on the step |

### State

What the assembly holds so the screens don't have to.

| State                    | Holds                                                                        |
| ------------------------ | ---------------------------------------------------------------------------- |
| `step`                   | The screen currently on the route.                                           |
| `name`                   | The full name; welcome greets its first word, the avatar shows its initials. |
| `avatarSrc`              | The picked photo, as a local object URL.                                     |
| `plan`                   | The `id` of the chosen plan.                                                 |
| `invites`                | The addresses sent so far, shown as the pending list.                        |
| `errors` / `emailsError` | Whatever the last submit rejected. Cleared on every move.                    |

## Notes

- The assembly is example code, the one file you are expected to rewrite. The screens stay as shipped.
- Skip links route plain left clicks only; modified and middle clicks go to the browser.
- The profile and invite forms are checked in the assembly, the way a form can on its own. Replace the checks with your requests.
- The photo stays in the browser as an object URL. Upload it instead, and pass back your URL.
- `onComplete` returns the flow to welcome and draws no success page; leaving is your router's job.
