## Usage

A sortable list lets the user put items in the order they want, like the slides of a deck in a sidebar. Drag an item by its handle, or use the keyboard.

<ForFramework fw="react">

```tsx
import { SortableList } from "@moderno-ui/react";
```

```tsx
const [slides, setSlides] = useState(["Cover", "Logo", "Colors"]);

<SortableList.Root
  items={slides}
  onReorder={(details) => setSlides(details.items)}
  aria-label="Slides"
>
  {slides.map((slide) => (
    <SortableList.Item key={slide} value={slide}>
      <SortableList.ItemHandle />
      <SortableList.ItemTrigger>{slide}</SortableList.ItemTrigger>
    </SortableList.Item>
  ))}
</SortableList.Root>;
```

</ForFramework>

<ForFramework fw="vue">

```ts
import { SortableList } from "@moderno-ui/vue";
```

```vue
<SortableList.Root v-model:items="slides" aria-label="Slides">
  <SortableList.Item v-for="slide in slides" :key="slide" :value="slide">
    <SortableList.ItemHandle />
    <SortableList.ItemTrigger>{{ slide }}</SortableList.ItemTrigger>
  </SortableList.Item>
</SortableList.Root>
```

</ForFramework>

<ForFramework fw="svelte">

```ts
import { SortableList } from "@moderno-ui/svelte";
```

```svelte
<SortableList.Root bind:items={slides} aria-label="Slides">
  {#each slides as slide (slide)}
    <SortableList.Item value={slide}>
      <SortableList.ItemHandle />
      <SortableList.ItemTrigger>{slide}</SortableList.ItemTrigger>
    </SortableList.Item>
  {/each}
</SortableList.Root>
```

</ForFramework>

<ForFramework fw="solid">

```tsx
import { SortableList } from "@moderno-ui/solid";
```

```tsx
const [slides, setSlides] = createSignal(["Cover", "Logo", "Colors"]);

<SortableList.Root
  items={slides()}
  onReorder={(details) => setSlides(details.items)}
  aria-label="Slides"
>
  <For each={slides()}>
    {(slide) => (
      <SortableList.Item value={slide}>
        <SortableList.ItemHandle />
        <SortableList.ItemTrigger>{slide}</SortableList.ItemTrigger>
      </SortableList.Item>
    )}
  </For>
</SortableList.Root>;
```

</ForFramework>

The list moves the items; your state keeps the order. Render the items in the order of `items`, and save the new order when `onReorder` runs.

## API Reference

### SortableList.Root

<PropsTable component="SortableList" />

| Prop           | Type                                                             | Default | Description                                                             |
| -------------- | ---------------------------------------------------------------- | ------- | ----------------------------------------------------------------------- |
| `items`        | `string[]`                                                       | —       | The items' values in their current order. Pair with `onReorder`.        |
| `defaultItems` | `string[]`                                                       | `[]`    | The first order, when the list keeps the order itself.                  |
| `onReorder`    | `(details: { items, value, from, to }) => void`                  | —       | Called after a drop in a new place, with the new order.                 |
| `disabled`     | `boolean`                                                        | `false` | No item moves. Focus and the items' buttons still work.                 |
| `size`         | `"sm" \| "md" \| "lg"`                                           | `"md"`  | Item height and text size.                                              |
| `translations` | `{ handleLabel, pickedUp, moved, dropped, cancelled }` (partial) | English | The handle's name and what a screen reader hears, for another language. |

`details.value` is the moved item, and `from` and `to` are its old and new places, counted from 0.

In Vue, bind the order with `v-model:items`, or listen with `@reorder`. In Svelte, use `bind:items`.

With `defaultItems`, the list keeps the order and hands it to its children: a function `(items) => …` in React, the default slot's `{ items }` in Vue, the `children` snippet's argument in Svelte, and a function that receives an accessor in Solid.

### SortableList.Item

| Prop       | Type      | Default | Description                                                             |
| ---------- | --------- | ------- | ----------------------------------------------------------------------- |
| `value`    | `string`  | —       | Required. One of the root's `items`.                                    |
| `label`    | `string`  | `value` | The item's name, for its handle ("Reorder Logo") and the announcements. |
| `disabled` | `boolean` | `false` | This item does not move. The others still move past it.                 |

### Parts

| Part                       | Element    | Description                                                                                  |
| -------------------------- | ---------- | -------------------------------------------------------------------------------------------- |
| `SortableList.Root`        | `<ul>`     | The list. Carries `data-size`.                                                               |
| `SortableList.Item`        | `<li>`     | One item. It holds any content: text, a thumbnail, buttons.                                  |
| `SortableList.ItemHandle`  | `<button>` | Optional. A grip, named "Reorder `label`". Only the handle drags. Children replace the icon. |
| `SortableList.ItemTrigger` | `<button>` | Required. The item's focus target, usually its name.                                         |

### Keyboard

| Key                                   | Action                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------- |
| `Tab`                                 | Moves focus into the list, then out of it. The list is one Tab stop.            |
| `ArrowDown`, `ArrowUp`                | Moves focus to the next or previous item.                                       |
| `Home`, `End`                         | Moves focus to the first or last item.                                          |
| `ArrowLeft`, `ArrowRight`             | Moves focus between an item's handle and its trigger.                           |
| `Space`                               | On the handle (or on the trigger of an item with no handle): picks the item up. |
| `ArrowDown`, `ArrowUp`, `Home`, `End` | While an item is picked up: moves it.                                           |
| `Space`, `Enter`                      | Drops the item. Focus stays on it.                                              |
| `Escape`                              | Puts the item back where it was.                                                |

A screen reader hears each step: "Logo picked up. Position 2 of 4.", "Moved to position 3.", "Dropped."

### Data attributes

| Attribute       | Values                                                                                  |
| --------------- | --------------------------------------------------------------------------------------- |
| `data-dragging` | `"pointer"` or `"keyboard"`, on the root and on the moving item, its handle and trigger |
| `data-settling` | On the root, for a moment after a drop                                                  |
| `data-disabled` | On the root when `disabled`, and on a disabled item and its handle                      |
| `data-value`    | On each item: its value                                                                 |
| `data-size`     | On the root: `"sm"`, `"md"` or `"lg"`                                                   |

## Notes

- The behaviour is a Zag machine in `@moderno-ui/core`, the same in all four frameworks.
- A press becomes a drag only after the pointer moves a few pixels, so a click on a button inside an item still works.
- Mouse, touch and pen all drag. On touch, the handle (or the item, with no handle) does not scroll the page.
- The moved item glides into place, unless the user asks for reduced motion.
