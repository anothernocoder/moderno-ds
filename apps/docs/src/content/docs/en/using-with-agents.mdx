## Set up

1. Add the `moderno` server to your agent's MCP config (Claude Code, Cursor and other MCP clients).

   ```json
   {
     "mcpServers": {
       "moderno": {
         "command": "npx",
         "args": ["-y", "@moderno-ui/mcp"]
       }
     }
   }
   ```

2. Start the agent from the project root, where `@moderno-ui/*` is installed.

3. Optional: write the rules and the loop below into `AGENTS.md` (`--claude` adds a `CLAUDE.md` twin).

   ```sh
   npx @moderno-ui/cli init --claude
   ```

- Local stdio server: no account, no hosted endpoint. Needs Node 22 or later.
- It reads `moderno.agent.json` from `node_modules/@moderno-ui/*` once, at startup.
- Answers match the installed versions, not the latest release.

## The theme's DESIGN.md

A theme added with the CLI brings its `DESIGN.md`: at the project root for a theme that replaces the default, or at `design/<theme>/DESIGN.md` for a brand theme. It holds the brand's values, the rules every Moderno theme follows and the brand's own notes. Mention it in `AGENTS.md` so the agent reads it before styling; the tools below cover the components and the contract.

## Tools

The tools read and verify; the agent writes the code itself.

| Tool                | Input                | Returns                                                                       |
| ------------------- | -------------------- | ----------------------------------------------------------------------------- |
| `search_components` | `query`, `framework` | Components ranked by intent, with import path and when to use.                |
| `get_component_api` | `name`, `framework`  | Props, `data-part`s and variants from the installed package.                  |
| `get_contract`      | none                 | Token slots, the dark-mode and multi-brand model, the `data-part` convention. |
| `get_examples`      | `name`, `framework`  | Working snippets in that framework's own syntax.                              |
| `validate_usage`    | `code`, `framework`  | Rule findings. An empty list means clean.                                     |

`framework` is one of `react`, `vue`, `svelte`, `solid` or `astro`.

## The agent loop

### 1. Search by intent

```
search_components({ query: "modal blocking decision", framework: "react" })
→ { matches: [{ name: "Dialog", score: 0.82, … }, { name: "Button", score: 0.11, … }] }
```

### 2. Read the installed API

```
get_component_api({ name: "Dialog", framework: "react" })
→ { package: "@moderno-ui/react", version: "0.3.0", framework: "react", component: { … } }
```

### 3. Check the contract

Do this before writing any colour, radius, spacing, elevation or container width.

```
get_contract()
→ { package: "@moderno-ui/tokens", slots: { color: ["--background", "--foreground", …] }, rules: […] }
```

### 4. Get a native example

Ask for the target framework instead of translating a React example by hand.

```
get_examples({ name: "Dialog", framework: "react" })
```

### 5. Write the code

```tsx
import { Button, Dialog, Portal } from "@moderno-ui/react";

<Dialog.Root>
  <Dialog.Trigger asChild>
    <Button variant="destructive">Delete account</Button>
  </Dialog.Trigger>
  <Portal>
    <Dialog.Backdrop />
    <Dialog.Positioner>
      <Dialog.Content>
        <Dialog.Title>Delete account?</Dialog.Title>
        <Dialog.CloseTrigger asChild>
          <Button variant="destructive">Confirm</Button>
        </Dialog.CloseTrigger>
      </Dialog.Content>
    </Dialog.Positioner>
  </Portal>
</Dialog.Root>;
```

### 6. Validate before finishing

Fix every finding and run it again until the list is empty.

```
validate_usage({ code: "…", framework: "react" })
→ { findings: [] }
```

```json
{
  "ruleId": "moderno/no-hardcoded-color",
  "severity": "error",
  "message": "Hardcoded color \"#ff0000\" bypasses the token contract — components may only reference a contract slot.",
  "suggestion": "Reference a contract color slot instead, e.g. var(--background)."
}
```

## Validation rules

| Rule                                 | Severity | Catches                                                                 |
| ------------------------------------ | -------- | ----------------------------------------------------------------------- |
| `moderno/no-hardcoded-color`         | error    | Hex, `rgb()`, `hsl()` and `oklch()` literals.                           |
| `moderno/no-hardcoded-dimension`     | error    | Literal `border-radius` lengths and arbitrary lengths like `w-[320px]`. |
| `moderno/valid-props`                | error    | Unknown props and invalid enum values.                                  |
| `moderno/no-raw-ark`                 | error    | Imports from `@ark-ui/*` or `@zag-js/*`.                                |
| `moderno/valid-data-part-override`   | error    | `data-scope` / `data-part` selectors naming a part that doesn't exist.  |
| `moderno/no-reimplemented-primitive` | warn     | Hand-rolled dialogs, native selects and variant-styled buttons.         |

## Golden rules

- Never edit components: theme them with CSS variables and vary them with props.
- Reference contract slots (`--background`, `--primary`, `--radius`, …), never hex colours, px spacing or ms durations.
- Put brand values in a theme, not in `@moderno-ui/tokens`.
- Keep `:root` light and `.dark` dark. Don't add a third theming mechanism.
- Import CSS only from `@moderno-ui/css`, never from internal paths.

## Lint in CI

[`@moderno-ui/lint`](https://www.npmjs.com/package/@moderno-ui/lint) runs the same rules as `validate_usage`, for people and CI.

```js
// eslint.config.js
import moderno from "@moderno-ui/lint";

export default [...moderno.configs.recommended];
```

```sh
npx moderno-lint src/**/*.tsx
```
